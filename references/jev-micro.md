# jev micro 层（可选 · 联网增强）

本文件把 `jev-chat` 的「单消息意图 / 张力判断 + 候选回复排序」能力接入本引擎，作为 macro 层的**可选 micro 增强**。

> **数据源铁律（重点：悬浮窗不要）**：micro 层只处理用户主动导入的材料（文本 / 文件 / JSON），**绝不引入悬浮窗、不接微信侧边栏、不做实时截图 OCR、不做任何常驻监听 / 自动抓取**。jev-chat 改造版已是「用户显式提交材料 → 一次性分析」，本引擎只引用其 `analyze.py` / `ingest.py`，不复制逻辑。任何「常驻在微信旁、自动捕获对话」的入口设想一律否决。

---

## 一、何时启用

| 入口 | micro 角色 | 触发 |
|---|---|---|
| **FULL · Step 4.5** | 增强 | 用户明确要求「帮我回 / 这条怎么回 / 判断一下」，或 FULL 显式开启 jev |
| **QUICK**（「这条怎么回」） | **主引擎** | 用户只问单条怎么回时，jev 是主体，macro 只做护栏 |

**不启用的情况**：用户没要求「回 / 判断」，且没开 jev → 纯离线，micro 完全不跑。

---

## 二、怎么调用（胶水层）

唯一新建脚本：`scripts/jev_bridge.py`。它 import `jev-chat` 的 `ingest.py` / `analyze.py`（依赖引用，不复制），把结果回贴成结构。

```bash
python scripts/jev_bridge.py <片段文件或原文> \
  --me <本人名>                # 来自 Step 1 的 isSender 归属判定，解决 jev「谁是我是必须确定」的铁律
  --reply-to <对方名>           # 回复对象；群聊时指定
  --relationship 恋人           # 场景固定
  --relationship-custom "<Step2 画像摘要>"   # 护栏：禁区 / 需求触发点 / 喜欢-抗拒的互动
  --context 10                  # 看最近几条
  -o jev_out.json
```

- **`--relationship-custom` 是护栏核心**：把 Step 2 画像卡（禁区、需求触发点、喜欢/抗拒的互动方式）喂给 jev，让它不只看最近 N 条，不被孤立片段带偏。
- 无 key / 模块不可达 / 调用失败 → 脚本返回 `{"enabled": false, "reason": ...}`，**上层据此走纯离线三档话术，不中断主流程**。
- `--dry-run` 不联网，用于离线自检 ingest + 调用链路（跳过 key 预检）。

## 三、micro 输出怎么读

`jev_bridge.py` 回贴的结构（`jev_out.json`）：

| 字段 | 含义 |
|---|---|
| `intent` | 对方真实意图（choice + 中文标签 + 置信度） |
| `danger_level.score` | 紧张度 0–9（0 没事，9 已爆发） |
| `best_action` | 建议动作（choice + 中文标签） |
| `partner_needs` | 对方当下要的是什么 |
| `candidates` | 3 条候选回复 + Jev 排序概率（按分数降序） |
| `confidence_note` | 置信度门控提示（见第四节） |

**呈现硬性要求**（沿用 jev 第 5 节）：
- 每条候选都要能被用户直接复制发送，不带编号 / 引号 / 解释后缀
- **必须写「另一种可能的解释」**——Jev 只看了最近 N 条，看不到线下完整关系
- 紧张度 ≥7 时，不给出轻松 / 调侃语气的候选
- 候选不够好就直说不好，不硬凑三条

## 四、七题判据速查 + 置信度门控

**七题**（jev 内核判断，详见 `jev-chat` 题库 `questions.py`，不要随手改判据）：

| 题 | 类型 | 判断什么 |
|---|---|---|
| `literal_question` | noul | 字面还是有潜台词（测试 / 讽刺 / 暗示 / 陷阱） |
| `true_intent` | choice | 真实意图：确认在意 / 发泄不满 / 要行动 / 要解释 / 闲聊 / 平和结束 |
| `danger_level` | score 0–9 | 离吵架 / 破裂有多近 |
| `should_reply_now` | noul | 下条该不该带实质内容 |
| `best_action` | choice | 核对记录 / 道歉 / 承诺 / 解释 / 回应理解 / 少说 / 排安排 |
| `partner_needs` | choice | 对方要的是道歉 / 行动 / 解释 / 在意 / 其实什么都不要了 |
| `tension_resolved` | noul | 张力是否真的化解了 |

**置信度门控（不要用直觉，用这张表；Jev 的排序能力 > 绝对概率值）**：

| Jev 给的 confidence | 怎么用 |
|---|---|
| ≥ 0.9 | 可以直接按 best_action 走 |
| 0.7 – 0.9 | 结论可用，但要在回复里带替代解释 |
| 0.5 – 0.7 | 只当线索，不当结论；明说「把握不大」 |
| < 0.5 | 相当于没答，改用直接读对话本身 |

**为什么不能把百分号当概率**：TypeSafe 自报的把握要保守——Banking77 意图分类里，Jev 自报 80–95% 把握的样本实际正确率只有 64%。所以用 Jev 挑最好的那条候选，**别用它算「有多大概率会吵架」**。

## 五、红线（micro 层必须保留）

1. **绝不替用户发送**——micro 只产候选，发送永远是人。
2. **不把百分比当概率**——呈现须带「另一种可能的解释」。
3. **macro 结论不被 micro 推翻**——jev 只看最近 N 条、看不到线下关系；阶段 / 画像结论优先级高于单消息判断。
4. **悬浮窗剔除、数据源不回退**——绝不引入悬浮窗 / 侧边栏 / 实时 OCR / 任何常驻监听；全程用户主动导入。
5. **截图归属推断须注明**——左右气泡推断时，回复里写「这段归属是我从位置推断的」。

---

## 六、隐私边界（沿用 jev 第 8 节）

- 只处理用户自己提交、有权查看的对话。
- key 只从环境变量读，**任何情况下不写进文件、不进 git、不进日志**；报错文本一律脱敏。
- 出网只有两次：一次给 Jev、一次给起草模型，都发给用户在环境变量里指定的那家。
- 结果 JSON 含对话原文，写文件时放用户自己的目录，别往公共位置丢。
