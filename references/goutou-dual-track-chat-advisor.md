# V2 双轨聊天参谋与回复谋划协议

本协议用于聊天策略、如何回复、继续交流和关系推进问题。它在双轨关系分析之上恢复并约束完整的聊天参谋能力；不得只给关系判断而省略可执行的聊天谋划。先对用户贴出的每句话执行 [逐句双轨协议](goutou-utterance-dual-analysis.md)，两套参谋方案须回指相应单元。

## 方案一：关系优势型聊天参谋

目标是在不操控对方的前提下，维护用户的选择空间、投入边界、互动节奏和互惠位置。

固定内容：

1. **形势与优势判断**：当前是谁提出话题、谁承担跟进成本、用户有什么选择；证据不足写无法评估。
2. **聊天策略和互动节奏**：本轮该继续、轻接、停止、转场还是修复；控制的是用户自己的投入，不用节奏制造对方焦虑。
3. **推荐回复话术**：行动代码允许时给一条最符合用户语气的文本；需要比较时最多给少量同权限版本。
4. **可能的下一步互动分支**：只写条件式预案，不预测对方心理或必然反应。
5. **风险与停止条件**：写明拒绝、不适、无回应、持续单向投入或现实成本达到什么情况时停止或改道。

## 方案二：客观共情型聊天参谋

目标是准确承接当前语境，兼顾双方可能的立场和感受，让表达清楚、自然、可拒绝。

固定内容：

1. **事实与沟通判断**：谁说了什么、草稿是否发送、当前话题是否有入口，以及哪些解释只是候选。
2. **双方立场与可能的感受**：分别呈现合理关切；使用“可能”，并保留替代解释，不虚构内心。
3. **推荐沟通策略**：回应核心内容、选择合适时机和清晰程度，不把理解等同认同或服从。
4. **推荐回复话术**：行动代码允许时给一条自然文本；冲突或拒绝场景只给必要的修复表达。
5. **可能的下一步互动分支**：按可观察回应准备后续，不为对方预写心理剧本。
6. **风险与停止条件**：明确何时暂停解释、停止追问或转为处理现实待办。

## 最终综合决策

两个方案之后必须给出：

- **行动代码**：`A 继续`、`B 轻接收束`、`C 不回复`、`D 另起话题` 或 `E 修复降压`。
- **推荐倾向**：方案一、方案二或融合两者。
- **理由**：说明当前证据下为何该倾向更兼顾用户利益、沟通效果和边界。
- **立即发送话术**：只在行动代码允许时给；与两方案的回复权限一致。

推荐融合不代表抹平差异。若两方案冲突，写清优先保护的利益、可能的关系成本和什么新反馈会改变推荐。

## 行动代码约束

| 代码 | 两轨可做 | 两轨不可做 |
|---|---|---|
| `A 继续` | 回应当前内容，维持自然节奏 | 借机连续加码或强行升级关系 |
| `B 轻接收束` | 最多一句承接，随后停止 | 追加问题、制造新任务 |
| `C 不回复` | 分析形势、安排观察条件和未来真实待办 | 生成用于立即发送的话术，包括“最后一句” |
| `D 另起话题` | 在合适时机用独立真实内容转场 | 用新话题绕过拒绝或掩饰追问 |
| `E 修复降压` | 承认边界、简短道歉、澄清共同责任或暂停 | 换话术继续推动同一要求 |

`C` 时两个方案的“推荐回复话术”字段都保留，并明确写“立即发送话术：不生成”。`E` 时若无需修复消息，也可不生成文本；不能为了填模板而打扰对方。

## 条件式互动分支

分支采用可观察条件，不写概率和确定预测。例如：

- 若对方主动追问或补充新信息，则回应其具体内容，再重新判断 A/B。
- 若对方只作礼貌确认且没有入口，则轻接一次或结束。
- 若对方明确拒绝或表示不适，则转为 E，停止推动原要求。
- 若没有新回复且无共同待办，则维持 C，不追加消息。
- 若出现需要确认的现实约定，则只处理待办，不夹带关系试探。

QUICK 每个方案通常保留 1–3 个高信息点和最多 2–3 条分支。完整分析可以展开证据、节奏、话术选择和更多条件分支，但仍不能把分支写成对方一定会怎样。

## 用户语言与幽默

优先复用用户自然的句长、称呼、口语程度和已出现的幽默方式，不模仿攻击性、贬低或试探性表达。没有用户语言样本时使用简短、日常、不过度热情的中文。明确拒绝、不适、冲突、道歉和严肃共同事项中，清楚与尊重优先，不强行加梗。

## 日常聊天三项校准

所谓“多分享、接情绪、见好就收”只能作为方向，不能机械执行。聊天参谋按以下方式校准：

### 1. 分享与提问平衡

- 优先回应对方当前内容，再补一小段相关自我分享；确有信息需要了解或对方留下入口时，至多增加一个自然问题。
- 连续问题、问完不分享容易形成面试感；只顾分享、不回应对方也会变成自我中心。判断标准是双方都有表达和选择话题的空间，不是固定比例。
- 对方明确询问时先直接回答，不用自我分享绕开问题；对方正在倾诉时也不急着抢回自己的故事。

### 2. 同时接事实与感受

- 先确认对方实际说了什么，再承接其明确表达的感受；感受没有明说时使用“听起来可能挺累”“你现在想聊聊还是先休息”等可校正表达，不替对方定性。
- “加班到十点”可以回应时间事实、关心状态或询问实际需要；问晚饭属于事实照顾，不应包装成已读懂隐藏情绪。
- 不强行积极、不比较痛苦、不立即解决；若涉及现实待办，情绪承接后仍需处理事实。

### 3. 自然收尾，不策略性抽身

- 在真实事务、精力下降、话题自然结束或对方已收尾时结束；可以简短说明，不必须每轮制造漂亮收尾。
- 不为留下余味而故意在热聊峰值消失、延迟或虚构“去忙”；这会滑向 push-pull。
- “晚点再聊”只在确有继续意愿时使用。没有明确后续安排可说“我先忙手头这个，回头聊”，不承诺具体回归时间。

两轨应用：方案一检查用户是否在承担全部开题、提问和维持成本；方案二检查是否准确回应内容与感受。若对方持续只有礼貌短答、无延展，则按 `B 轻接收束` 或 `C 不回复`，不靠更多问题救场。

## 高负荷沟通与反馈循环

当消息包含多个争点、公开或第三方压力、反复解释或明显的追问—退缩循环时，另读 [沟通框架、群体影响与反馈循环](communication-framing-and-feedback.md)：

- **一个主要目的**：本轮只完成告知、立场、请求、安排、修复或结束中的一个主要目的；多个现实待办分项处理，但不删去影响选择的重要事实。
- **接收条件**：核对必要背景、关键词含义、当下精力和事实误解。所谓接收方视角是减少误解，不是设计对方的认知。
- **公开与私下分开**：朋友、家人、群聊或公开场合中的回应只算该情境证据；关系定义、性、财务和重大承诺应在低压力、可拒绝条件下重新确认。
- **先画循环**：按触发、行动、回应、反馈延迟、解释、补偿和下一轮还原序列；模式可以共同形成，不直接证明谁在故意操控。
- **小幅调整**：一次只改变一个可控变量，并用可观察结果决定是否继续。不得用突然热情、冷淡、失联或竞争展示制造反馈。

方案一据此控制用户自己的投入、解释和修复成本；方案二据此提高信息清晰度并保留替代解释。立场已清楚且无新事实时回到四步法停止重复解释，不为测试循环追加消息。

## 分歧沟通四步法

用户询问价值观、财务、家庭、关系期待或相处方式分歧时，另读 [边界与共同责任](goutou-boundaries-and-mutual-responsibility.md)，按 **表达立场 → 确认分歧 → 尊重对方 → 停止重复解释** 组织两套聊天参谋：

- **方案一 / A 轨**：简洁表达用户的真实立场、可承担范围和选择；确认差异后停止增加解释成本，不以让步换取认可。
- **方案二 / B 轨**：准确复述双方具体差异，承认对方的选择权，不把理解写成认同，也不推断对方人格或动机。
- **行动代码**：刚造成压力或需要收回说服时用 `E 修复降压`；立场已清楚、无共同待办时用 `C 不回复`；只有出现新事实、新方案或现实待办时才重新判断 `A 继续`。

停止重复解释不等于逃避共同责任。存在共同承诺、行程、账务、照护、重大财务或安全事项时，停止说服立场，继续只谈事实、影响、责任、期限和可选方案。

## 关系推进任务的附加判断

用户询问升温、见面互动、自我披露、见面后反馈或推进节奏时，另读 [关系推进与节奏校准协议](goutou-relationship-progression-and-pacing.md)。先检查投入动机、身体同意和重要信息披露，再综合主动延展、回应质量、现实投入、邀约兑现与边界反馈分流：

- **正向反馈**：通常对应 `A 继续`，但一次只推进一项；不得把当前回应扩张成身体接触、关系确认或连续邀约的许可。
- **有限反馈**：通常对应 `B 轻接收束`；只有存在独立真实内容且不是绕过拒绝时才考虑 `D 另起话题`。
- **负向或边界反馈**：造成压力时用 `E 修复降压`；无需修复且没有现实待办时用 `C 不回复`。
- **无法判断**：样本少、时间不可靠或外部限制未排除时，选择对对方负担更小的相邻代码，不通过增加消息强行取证。

用户询问何时邀约时，把互动顺畅、主动分享具体兴趣或时间、以及无未处理冲突的自然回暖视为**一次邀约入口**，而不是好感或见面意愿的证明。邀请使用具体活动、必要的时间范围和可拒绝表达；对方拒绝后停止，含糊推迟且不反提时不连续追约，对方给出替代时间时再处理安排。不得用邀约挽救已经结束的话题，也不得利用低落、脆弱或“怕再次疏远”的推测推进。

降低主动频率时必须区分“停止单向消耗”和“制造对方焦虑”：前者可以建议，后者必须拦截。不得把计划性冷热、故意晚回、失联、虚构忙碌、制造嫉妒、展示其他异性或“征服/高位”话术作为关系优势方案。稳定、真实、可持续的关心不因其温柔或主动就被判为讨好。

## 当前节奏策略：日报与阶段总结

当用户采用“刷一下，她愿意聊就聊，不愿意聊就先后撤”的近期策略时，将口语“刷一下”解释为有真实内容的轻量联系，不是无内容测试、连续打卡或反复确认存在感。

### 规则一：轻触—响应—收束

- 只在有自然话题、生活分享、共同兴趣或现实待办时轻量开启。
- 若对方主动追问、补充信息、接梗或提出下一步，则正常聊，保持与其投入大致匹配。
- 若只有礼貌回应而无入口，则最多轻接收束；若未回复或明确不愿聊，则不追加。
- “后撤”仅指停止当前追问并回到自己的安排，不虚构忙碌、不惩罚、不故意忽冷忽热。

### 规则二：1–2 周低压力观察窗

- 将策略作为一到两周的观察窗，而不是每天必须执行的联系计划；联系由真实内容和对方反馈触发。
- 适当间隔用于避免单向消耗和尊重双方节奏，不用于制造稀缺、落差或依赖。
- “可能产生好奇”只是候选机制。支持证据包括对方主动发起、追问用户近况、回访旧话题、主动分享或提出下一步；普通礼貌回复、单个表情和一次回复变快不够。
- 同时保留其他解释，例如对方当时有空、话题本身相关或现实待办需要回应。
- 明确拒绝、不适、连续缺乏互惠或只有用户反复发起时提前停止或调整，不为凑满 1–2 周继续联系。

日报写当天执行与反馈，不安排强制的“明天再刷”。阶段总结以完整观察窗为单位，判断继续、调整或停止；不得写成“坚持两周她就会好奇”。
