# V2 案例反馈与复盘

复盘用于校正一次判断，不把单个案例升级成对某类人或某段关系的普遍定律。长期保存复盘内容仍需遵循授权记忆规则。

## 记录结构

| 字段 | 内容 |
|---|---|
| 原始范围 | 当时实际读取的消息、日期和来源 |
| 原决策 | A–E 代码、事实依据、未知项和停止条件 |
| 实际行动 | 用户是否发送、发送了什么；草稿和已发送内容分开 |
| 可观察后续 | 对方原话、现实安排是否发生、是否继续或停止 |
| 节奏策略 | 当天是否轻触、对方是否延展、用户是否及时收束；当前 1–2 周观察窗进度 |
| 判断偏差 | 漏掉事实、来源归属错误、边界分类错误或过度解读 |
| 局部修正 | 只修正能被该案例支持的规则或措辞 |

## 复盘问题

1. 当时是否把推断写成了事实，或把未发送草稿算成已发生互动？
2. A–E 决策是否服从边界优先级？
3. 实际后续支持的是哪项可观察判断，哪些仍然未知？
4. 建议是否给了清楚、可拒绝、可调整的行动和停止条件？
5. 这次偏差来自规则、材料不足、说话人归属还是执行差异？
6. 本次是否遵循“有真实内容才轻触、愿意聊就聊、没有入口就收束”？适当间隔是在保护节奏，还是变成了刻意制造落差？
7. 若处于 1–2 周观察窗，对方的主动发起、追问、回访话题或提出下一步有哪些可核对证据？没有证据时不得写成“已经产生好奇”。

用户纠正优先更新事实账本。只有在多个可比案例中重复出现、且替代解释被核对后，才考虑调整一般路由。不要根据一次积极回应推导“这种话术有效”，也不要根据一次沉默推导人格或感情结论。

## 双向复盘

同时检查用户的表达分寸和对方实际表达的边界。允许指出用户可能造成的压力，也允许指出对方在共同承诺上含糊、失约或回避；评价围绕行为、影响和证据，不用人格、修行或情商标签给双方排高低。
