# V2 情境感知决策协议

本协议用于“要不要回、怎么回、是否另起话题”。它约束即时话术，不取代完整聊天分析。事实取证和边界规则优先于本协议。

## 五项定性观察

只使用 `存在`、`缺少`、`不明确` 等定性结论，并附可观察依据。

| 指标 | 观察问题 | 不能据此断言 |
|---|---|---|
| 主动扩展 | 对方是否追问、主动分享或提出下一步 | 好感程度 |
| 话题延展 | 当前回复是否留下自然、具体的接话入口 | 一定希望继续聊 |
| 情绪语气 | 原文明示玩笑、平静、不悦、困扰或拒绝吗 | 隐藏心理动机 |
| 边界自主 | 对方是否明确说没空、不想聊、不愿改变或不同意 | 对整段关系的永久态度 |
| 相邻情境 | 是否刚有冲突、现实约定、共同待办或合适的新内容 | 未记录的线下状态 |

回复间隔、表情、字数和单次未回复可补充事实，不能单独决定关系含义。

## A–E 决策闸门

按优先级选择一个主决策：

| 决策 | 适用条件 | 输出限制 |
|---|---|---|
| `E 修复降压` | 明确拒绝、不适、冲突，或用户表达造成压力 | 只承认边界、澄清共同责任或暂停；不继续说服 |
| `A 继续` | 对方主动追问、分享新信息、提出下一步或留下明确入口 | 正常回答当前内容，不过度加码 |
| `C 不回复` | 对方明确收尾、没有回复且无待办，或话题自然结束 | 不生成可发送文本 |
| `D 另起话题` | 有独立的新信息、共同兴趣或未完成现实约定，且不是绕过拒绝 | 与旧话题分开，在合适时机开启 |
| `B 轻接收束` | 对方礼貌回应但没有新入口，简短承接有实际价值 | 最多一句，不追问、不制造新任务 |

若证据不足以区分相邻决策，选择对对方负担更小的一个，并说明缺口。`D` 不能用来绕过 `E`；同一要求被拒绝后，换话题、换措辞或隔一会儿重提仍属于继续推动。

## QUICK 输出

默认格式：

```text
方案一｜关系优势型聊天参谋（结果 A）
- 形势/节奏：当前没有新的对方投入，追加消息会增加用户单向投入；维持停止状态。
- 推荐回复话术：立即发送话术不生成。
- 条件分支：若对方主动开启新内容则重新判断；若仍无回复且无待办则不追加。
- 风险与停止条件：不要把沉默当试探；没有真实待办时停止。

方案二｜客观共情型聊天参谋（结果 B）
- 判断/策略：对方最后一条是明确收尾；可能只是结束当前话题，动机无法确认。
- 推荐回复话术：立即发送话术不生成。
- 条件分支：若出现现实待办则只处理待办；若对方明确不适则转 E。
- 风险与停止条件：不猜测心理，不用解释填补沉默。

最终综合决策
- 行动代码：C 不回复。
- 推荐倾向：融合两者。
- 理由：既避免单向追加，也尊重当前话题已经结束的事实。
- 立即发送话术：不生成。
```

只有允许发送时才增加一条文本：

```text
方案一｜关系优势型聊天参谋（结果 A）：简短承接，不追加问题；若对方没有新内容则停止。
推荐回复话术：好，知道啦，你先忙。
方案二｜客观共情型聊天参谋（结果 B）：回应其“先忙”的语境，不推断动机；若对方稍后主动再正常接话。
推荐回复话术：好，你先忙。
最终综合决策：B 轻接收束；推荐融合两者。立即发送话术：好，你先忙。
停止条件：发出后不再追问；等对方主动或出现真实待办。
```

方案一和方案二都必须出现，但 QUICK 可压缩。不要同时给五种话术让用户继续试探。用户明确要求多个语气版本时，可以在同一行动代码范围内给 2–3 个版本，但不能改变回复权限或把条件分支写成预测。

## 结构化复核

需要回归测试规则时，可将已经人工确认的观察交给 `scripts/conversation_gate.py`。脚本只执行决策优先级，不解析自然语言、截图或心理状态；脚本输出不能替代回原文核对。
