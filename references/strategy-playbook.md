# 策略层（狗头军师核心）

心理模型只提供候选解释，这一层给“怎么办”。三个产出：**关系阶段 → 风险清单 → 与用户目标相称的短期行动 + 话术**。

---

## 〇、目标和边界（吸收 schema 2.0）

**按当前用户目标给建议**：理解、澄清、改善互动、表达边界或结束联系。**不能默认"维持并推进关系"是唯一正确目标。**

- **用户与对方都可以拒绝邀约、延后回复或停止联系**，不因其选择自动判定为惩罚或人格缺点。
- **建议基于原文明确需求、可核对的行为及用户目标。** 不要安排冷热交替、虚构忙碌、羞辱、嫉妒刺激或利用对方弱点来逼迫回应。
- **遇到明确威胁、强迫或持续骚扰，先考虑安全与退出**，不能被"渐进影响"覆盖。用户想结束联系时尊重该目标。
- **冲突时的优先级**：用户的退出目标与双方明确边界 **>** R1–R4 与「三档话术/字数纪律/50% 留白」等推进类纪律。后者只在「默认要继续推进关系」时生效。

## 一、关系阶段判断

阶段不是线性必经，也可能回退。判据以**指标为主、内容为辅**。

| 阶段 | 判据（指标 + 内容） | 主要风险 | 行动原则 |
|---|---|---|---|
| **初识** | 会话段 <5，句长短，零自我披露 | 无存在感 | 建立可识别的记忆点，不要急着拉频率 |
| **破冰** | 回应率上升，出现提问，句长开始变长 | 话题枯竭 | 找到 1–2 个高频共振话题，围绕它铺 |
| **试探** | 双向提问率上升，出现日常分享，回应速度快 | 一方升温更快 | 用「小邀约」测试，不一次押注 |
| **暧昧（早）** | 深夜占比上升、秒回比例上升、出现专属称呼/emoji | 主要是暧昧错觉 | 把线上热度转成线下接触 |
| **暧昧后期** | 亲密与激情证据较多，但承诺证据有限 | 期待长期错位 | 需要时做一次明确、可拒绝的关系澄清 |
| **确定** | 出现明确关系表述、排他性表达、共同计划 | 期望错位 | 对齐期待，别默认对方理解一致 |
| **稳定** | 三项都有持续、跨情境的行为证据 | 惯性化 | 保持共同体验与独立生活 |
| **倦怠/危机** | 多窗口互惠下降，负向互动增加且修复减少 | 沉默螺旋 | **先停止加压，再评估双方是否愿意修复** |

**阶段判断必须用 2 条以上指标交叉验证。** 单靠「聊得多」判断为暧昧是最常见的错误——高频也可能只是对方礼貌。

## 二、风险识别

诊断完先列风险，再给方案。每条风险格式：**现象 → 证据 → 机理解释 → 后果**。

| 风险 | 触发指标 | 说明 |
|---|---|---|
| 投入不对称 | `initiative_skew` ≥0.3 或 `volume_skew` ≥0.35 | 长期单边投入会转化为 resentment |
| 追逃循环 | A 延迟↑ → B 频率↑ → A 延迟↑↑ | 越追越远，必须让追方减速 |
| 单向输出 | `max_streak` ≥3 反复出现 | 对方在承受，不在交流 |
| 互动持续未被接住 | 多个可比较窗口中，背离/对抗增加且缺少修复 | 单向投入与失望可能累积 |
| 承诺证据有限 | 表达、选择与兑现长期不一致 | 需要澄清期待或停止单向加码 |
| 沉默螺旋 | `momentum_recent_vs_base` 连续下滑 + 敷衍率上升 | 拖得越久越难重启 |
| 期望错位 | 双方对关系的表述明显不一致 | 必须在升级前对齐 |
| 外部压力 | 出现第三方/家庭/工作压力话题 | 有时降温与你无关 |

## 三、短期行动方案

固定三段式，**不做什么比做什么更重要**。

```markdown
### 下一观察窗口

**做**
1. {具体动作} —— 触发时机：{什么时候做}
2. …（不超过 3 条，多了做不到）

**不做**
1. {具体禁止项} —— 原因：{对应哪条风险}
2. …

**观察**
- 观察指标：{回应率 / 是否主动开启 / 是否延伸话题}
- 窗口结束后复盘：{达到什么信号说明有效，什么信号说明需要调整；窗口长度按事件和用户目标确定}
```

规则：

- **「做」不超过 3 条。** 行动方案失败通常是因为条目太多。
- **每条「做」都要绑定触发时机**，否则等于没说。
- **「不做」直接从风险清单反推**，一一对应。
- **必须有可验证的观察指标**，让用户 7 天后能自己判断有没有效。

### 常见情形的处方原则

| 情形 | 核心原则 |
|---|---|
| 投入不对称（你投入更多） | **降频而非加码**。把发起频率降到与对方相当，观察对方是否补位 |
| 追逃循环 | 追方停止追问与求证，给足 5–7 天；同时保持低频、无压力的日常友好 |
| 暧昧卡死 | 一次明确的、具体的、可拒绝的邀约（给对方留退路），而不是表白式逼问 |
| 对方降温 | 先排除外部因素（工作/健康/作息），再决定是否介入 |
| 四骑士出现 | 停止辩论对错，先停止伤害；蔑视出现时必须明确表达边界 |
| 你想结束 | 直接、清晰、不指责，不留模糊余地 |

## 四、话术生成

### 三档输出

同一情境给三档，让用户按自己的风险偏好选：

| 档位 | 特点 | 适用 |
|---|---|---|
| **保守** | 不带要求，最易被接住 | 关系脆弱、对方在回避 |
| **标准** | 有明确意图但留空间 | 大多数情况 |
| **推进** | 明确表达或邀约 | 暧昧后期、需要破局 |

### 字数红线与话术建议

字数上限是话术形式的唯一硬性限制，其余写法按语境灵活选择。各档分别计数；同一轮分成多条发送时合计不得超过上限。对方无有效文字时，不生成文字回复。

1. **建议引用真实语境。** 用聊天里出现过的具体细节（那家日料、那个展、对方提过的事），通用模板一眼假。
2. **字数上限 = 对方上一条消息字数 × 1。** 对方这条发 N 字，你最多回 N 字。
   取的是**对方上一条消息的实际字数**（去表情/媒体标签后），不是他的 `char_avg`。

   | 对方消息 | 你的上限 |
   |---|---|
   | 40 字 | ≤ 40 字 |
   | 15 字 | ≤ 15 字 |
   | 1 字（「嗯」「好」） | ≤ 1 字 |

   极短消息同样按 1 倍计算；对方发「嗯」时，回复最多 1 字。
   对方发「嗯」这类低投入回复时，更好的选择是**不接或延后**，而不是硬凑一句。

   **边界（收尾语回溯）**：若对方上一条是**纯收尾 / 无实质内容**（「好的」「嗯」「哦」、单表情、单图片无文字），该条**不作为基数**——直接套用会把「重新开口」这个动作数学锁死（≤2 字根本无法开口）。此时**回溯到对方上一条实质消息**取基数；若整段对话都无实质消息，开口默认上限取 **30 字**（短开口档）。
   确实需要长解释时：先发一句 ≤ 上限的短句回应，等对方接话后再补充，不要一次倾倒。
3. **给对方留退路。** 邀约类话术建议包含可无压力拒绝的结构（「不行也没关系」「你定」）。
4. **一次一个问题。** 连续追问是压迫感的主要来源。
5. **不解释情绪，只陈述事实 + 表达感受。** 「你都不回我」是批评，「我这两天有点不安」是表达。
6. **谨慎用反问句表达不满。** 反问容易被读作攻击；若必须反馈，优先用具体事实、影响和可拒绝请求。
7. **每条话术标注「如果对方这样回，你接着怎么做」。** 只给开头不给后续等于没给。

### 三条实战铁律（2026-09-23 由用户确立，任何时候优先生效）

这三条是**跨关系、跨场景的通用军规**，优先级高于任何具体话术技巧。每次生成话术之前先过一遍这三条。

#### 军规 1 ·【只点射，不扫射】——只指出细节，绝不给细节写说明书

看到好玩的东西，**只说出那个名词/现象**（"钱字垫子""AirPods""假发"），然后停。

**绝不自作主张替对方总结**"这意味着什么""因为什么""有什么玄学"。解释权和笑出来的权力，留给对方。

- ❌ 反例（39 字）：红石榴配"钱"字鼠标垫，杜总这下午茶主打一个招财暴富[机智] 难怪前天能博了个状元，看来都是有玄学的[偷笑]
  → 把"钱字垫子"这个好观察，用一句"招财暴富"+一句"玄学"解释干净了。对方只剩"哈哈"可回，话题一次讲完。
- ✅ 正例（6 字）：**钱字垫子亮了**
  → 只标出被看见的东西。她自己会反应过来"我桌上确实有个钱字垫子"，然后接话。

#### 军规 2 ·【50% 留白法则】——永远只说半句话

**永不**在一个气泡里把"起承转合"全演完。你只负责抛上联（观察），下联（反馈）留给对方去对。

- 自检：这条消息读完之后，**对方还有没有可接的东西**？如果答案是"只能回哈哈/表情"，就是演完了，砍到只剩上联。
- 与字数红线协同：字数上限（对方上一条 ×1）是硬约束，留白法则是**质量约束**——即使字数允许，也不要塞满。

#### 军规 3 ·【无时差原则】——禁止主动打时间戳

除非**敲定具体约会时间**，日常闲聊中严禁主动使用跨越时间的词汇：**"前天""昨天这个时候""好几天没聊""上次""这两天"**。

保持"一直在当下"的松弛感，不制造时间距离感。

- 为什么：主动打时间戳 = **主动提醒对方"我们有过沉默"**。对方本来没在意，你一提就替她记起了账。这等同于"付出陈述"的隐性变体，同样是把话题拉进算账框架。
- ❌ 反例："难怪前天能博了个状元""这两天你没消息"（后者仅在**必须重启长静默**时作为例外，条件见下方「纪律边界」——≥48h 无消息且最后发言人是对方，且仅限一次）
- ✅ 正例：直接说当下这件事，不交代它发生在哪天。

> **纪律边界**：军规 3 的唯一例外是**长期静默后的重新开口**（≥48h 无消息且最后发言人是对方）。此时"时间差"本身就是需要被承认的事实，回避它反而显得刻意。除这一种情形外，一律适用。

### 战术纪律（9/24–9/25 实战验证，跨关系通用）

- **不处表态位**：任何消息发完，对方都要有「无痛说『不』」的空间。邀约必须可拒绝；玩笑层（如对方玩笑说「明天带给我吃」）停在记账层，不一步跳三选一餐厅。
- **先给后取**：想看对方日常 / 让她分享，自己先晒一条（状态 / 照片），她才好无压力回镜；直接「分享一下 / 带我见世面」＝把她架到表演位，偏压偏舔。
- **等她先动、稳接**（条件适用：对方焦虑依恋且主动推进、你偏安全 / 低需求感）：纪律是稳接而非抢开题；抢开题易把对方推回防御，也浪费她主动给的球。**适用范围＝日常闲聊的开口节奏，不适用于阶段推进**——暧昧后期仍需一次明确、可拒的邀约（见动机护栏 C 判定边界），静止不动同样违规；别把本条读成「永远等她」。
- **偶发冷场不补枪（元纪律）**：偶发冷场是双向容错额度，不必上纲；补枪才把冷场坐实成僵局。
- **给空间 = 减压，不是变冷**（条件适用：对方焦虑依恋）：停止的是**主动加压动作**（抛邀约、连发、追问、索要分享、求回应），**不是**停止回应。对方主动来消息时仍按**正常温度**稳接——不刻意延迟、不缩短、不阴阳。从「高频热烈」骤降为「故意沉默 / 冷回 / 敷衍」＝策略性冷热交替，命中红线 R1。**判定法**：给空间后你的**回应质量应持平**（同样的 warmth），只是**主动发起变少**；若对方感到温度掉了，就是越线。
- **给空间的动机必须自查**：正确动机是「我减压 / 不再 push」，错误动机是「让她着急 / 让她尝尝」——后者是惩罚性沉默，同样命中 R1。感到委屈或愤怒时尤其要过这一条。
- **目标 ≠ 手段（防止自伤）**：「等她先动」的目的是**接住她的球**，不是**拒绝她的球**。对方主动推进——尤其**主动约见**——正是本条纪律一直在等的信号，除非存在真实日程冲突，一律接住；为「立规矩 / 制造落差 / 求对等」而回绝＝亲手关掉自己一直在等的窗口，且命中 R1 / R3。
- **「展示忙碌」的频率边界（防止从展示滑成冷热）**：真实忙碌可以展示（动机护栏 B），但必须是**真有冲突时才发生**、且**每次带反提**。若对方连续两次主动邀约都被回绝，已从「偶尔」滑成「模式」——在高焦虑方看来等同冷淡，命中 R1。**判定法：回绝率 ≤ 1/2，且每次必给反提。** 绝不为「点一下让她知道」而制造冲突（＝虚构忙碌，R1 + R2）。
- **展示忙碌的两个执行细节**：① 理由必须是**当下的真实状态**，不能用历史记录充当今天的证据（对方问的是今天，不是上周；今天真不忙就别拿「忙」当理由，改真实原因）；② **不向对方举证**——不主动发打卡截图 / 排班表去证明自己忙。**举证＝怕她不信＝需求感暴露**；知道自己忙的人不需要出示证据。证据是给自己决策用的，不是拿来给对方看的。
- **归因纪律（禁止从失败样本归纳错因果）**：连续邀约失败时，先核失败的**真实原因**是「对方客观不可用」（异地 / 已有安排 / 医美恢复 / 身体）还是「对方不愿」。若属前者，**提前量不是解药，可用性才是**——把可用性问题误读成态度问题或规则问题，会导出「必须提前 N 天」「当天约一定不成」这类伪规律，进而催生惩罚性立规矩（命中 R3）。**样本 n ≤ 2 时不得归纳规则**，只记录单个事实。
- **怀疑对方诚意 → 设计一次可证伪检验，不反复猜**：当用户出现「她是不是在耍我 / 遛我 / 根本不想见我」这类怀疑时，**不要靠感觉反复安抚，也不要反复质疑**（两者都消耗信任且无进展）。做法：约定**一次**干净的检验动作——通常就是一个符合「明确时间 + 明确地点 + 可无痛拒绝」三要件的邀约——并**事先写明判定标准**：接受 → 怀疑不成立，归因回到时机 / 可用性；**含糊拒绝且不反提** → 怀疑成立，届时重新评估，不粉饰。**检验只做一次**，不得重复施压或做成连续追问。
- **信号兑现率（把「她是不是在耍我」变成可算的数）**：当用户怀疑对方「给信号又不落地 / 在遛我」时，不要凭感觉反复争论，改为统计 **signal → follow-through**：
  1. 列出对方抛出的**意向信号**（「应该买票去看闽超的」「回泉州后去走走」「改天一起」）。
  2. 标记每条的结局：**兑现 / 未兑现但理由可验证 / 未兑现且理由不可验证 / 拒绝时是否反提**。
  3. 判定：
     - 信号多、**拒绝时不反提**、理由**不可验证** → 意向不足（是真的在遛），按 P4 的单次可证伪检验确认后重新评估。
     - 信号多、未兑现但**每次都给可验证的真实理由**（真回家了、人确实在老家） → **可用性问题，不是态度问题**，解药是等对方进入可用状态，不是惩罚。
     - **关键区分点只有两个：理由可验证性 + 有无反提。** 其余都是猜测。
  4. 这份记账本身就是给用户看的——**把模糊的「她到底什么意思」变成一张能对账的表**，用户的焦虑有了落点，也就不再需要用「制造落差」这种动作去试探。
- **进度多维不同步（诊断纪律）**：关系推进不是单一标量，**言语亲密 / 见面频率 / 肢体亲密 / 承诺度**四条线可以异步推进。常见形态是「言语很热、肢体零推进」（**verbal 爱 ≠ physical 步**）。诊断必须**分维度看**：定位哪一维缺少证据，再用清楚、可拒绝的沟通或邀约核验，不能为了“补进度”推动身体接触。**禁止**用「她嘴上很亲」否认「肢体没动」，也**禁止**用「累计见面多」掩盖「近期新增见面已停滞」。用户感觉到的落差，多数来自这类异步——先定位维度，再判断是否适合澄清、观察或停止，不要笼统下「关系好 / 不好」的结论。

### 关系推进的物理层与表达层（10/22 实战提炼 · 可复用）

本小节处理一类 skill 其他章节没单独覆盖的情形：**当对方把"真实性"主要锚定在线下、且用行为而非语言确认关系时**，推进怎么走。从清峰×柒月案例提炼，通用化为下述原则。

#### 物理层原则 · 线下真实感

- 部分对象（尤其高焦虑 + 重视"在一起的真实感"者）认知里**线下当面互动才是真实的，线上聊天分量天然低于线下**。此时关系推进、确认、表达的质量锚在"你面对面是什么样"，不在对话框里打什么。
- 推论：**线上任何确认/表达都替换不了线下**；隔着屏幕的"确认话术"不仅场景错，而且在对方框架里根本不算数。确认/语言推进必须发生在面对面。
- 用法：判这类对象的推进，盯**行为层**（见面频率、身体接触、在场状态），不拿"他说没说我们"当唯一标尺。

#### 身体接触与语言确认均需可拒绝

- 线下互动、身体接触和关系确认可以异步发展，没有固定的“先身体后语言”或“先语言后身体”顺序。根据双方已经明确表达的意愿、关系阶段和具体情境选择下一步。
- 牵手、拥抱等身体接触需要明确询问或双方已经清楚建立且可随时撤回的互动惯例；靠近、玩笑、撒娇、接受照顾、没有躲开或一次接住都不能单独视为同意，更不能称为关系“绿灯”。
- 对方拒绝、回避、僵硬或表示不适时立即停止，不换动作继续测试。一次同意只适用于当次具体行为，不自动授权后续升级。
- 语言确认同样需要可拒绝，不在冲突、压力或对方刚表达边界时逼迫表态。线上或线下都可以沟通，选择双方更能清楚表达的场景，不把面对面规定为唯一有效形式。
- 分享梦境或假定场景只能基于真实、自发表达，不编造内容测试反应，也不把对方接梗解释为身体接触或关系确认的同意。

#### 微纪律（与三条实战铁律 / 战术纪律互补，从实战提炼）

- **指令后闭嘴**：对方当面给你改进指令（"讲人话/加标点/别装/自然点"）= 在给你指令不是聊天；正解=认一句+停，绝不连发解释/表演（被下令"别装"后还继续表演，是高频扣分项）。
- **接住正面标签并轻推**：对方给正面评价（"讲义气/靠谱/细心"）= 主动亮绿灯，认下 + 往关系推半步（"对别人这样，对你更得是"）；忌用玩笑梗把标签扔掉、流失绿灯。
- **亲昵吐槽＝待结合语境的微小信号**：它可能是舒适、玩笑，也可能是真实不满。检查双方既有语气、对方后续和边界；轻接住或澄清即可，不当作亲密进度条。
- **不抢确认＝最优节奏**：对方防御型、要"不被推进"时，你不抢着确认关系＝给对方推进腾空间，与"对方也想推进"不矛盾（对方靠交底/给信号/靠近自走）。
- **被看穿从容**：被看穿/误发/尴尬时，不慌·不武器化·不点破·显不在意＝加分（对照"演/装"是另一极）；越把它当"需要补救的事件"，越容易重演"装"。

### 表达质感 · 说人话（10/22 实战提炼 · 可复用）

话术再合规，读起来像机翻、绕、抽象，照样被对方判为「不真诚」「装」。本小节处理一类其他章节没单独覆盖的情形：**消息的"人味"**——让发出去的字像真人随手打的，不是 AI 写的、不是说明书。

从清峰×柒月案例提炼（对方在 10/22 当场两次纠正：「讲人话」「加点标点符号，大哥」），通用化为下述原则。

#### 四条表达纪律

1. **说人话，不概念化**
   - 不用抽象名词／术语／概念化描述代替真实感受与具体事件。对方要的是"你这个人真实在想什么、做了什么"，不是分析框架。
   - ❌「你对我的意义更多是一种…」「这反映出我们之间…」「我本质上是一个…」「我比较被动、有点边界、可能还要顾及你的敏感微微推演」
   - ✅「我昨天路过那家店想起你」「我就是想多陪陪你」「你昨天问的那些问题我挺开心的」
   - 自检：这条读完，对方能不能**立刻懂你在说一件具体的事**？要她"翻译"才懂，就是没说人话。

2. **加口语词，语气松弛**
   - 适当用「呗／哈／嘛／啦／呀」等语气词，让语气自然下垂、像聊天不是写稿。
   - 分寸：口语词是"松弛感"不是"卖萌"；对方严肃／交底话题时不撒娇语气词，否则轻佻。
   - 与军规 2（50% 留白）协同：语气松弛 ≠ 把话说满。

3. **加标点符号，主动断句**
   - 长消息必须断句——该逗号逗号、该句号句号，**不要一整段无标点**（对方会读两遍才懂，直接要你"加标点"）。
   - 一条里塞多个意思时，用换行或标点分成 2–3 句，别堆成一段。
   - 自检：这条能否**一口气读完不喘气**？不能就断。

4. **文字通顺，不跳跃不绕**
   - 逻辑连贯，一句接一句；别从 A 跳到 Z 再回 B（自嗨式联想），别用「遥控器认错／日子快过不下去」这种对方看不懂的起手。
   - 一个气泡只讲一件具体事（军规 1／留白已覆盖"只说半句"，此处强调"这一件"要讲顺、讲完）。
   - 想解释清楚时，用"具体一件事 ＋ 我的感受"两句就够，不铺陈背景。

#### 与既有纪律的关系

- 本小节是**表达层质感**，不重复军规 1–3（说什么／留白／时差）、不重复字数红线（字数），专管"怎么说才像人说的话"。
- 命中本小节的典型场景：对方说「你讲人话」「加点标点」「你这说的什么」「自然就好」→ 这是她在给你**表达指令**（见微纪律"指令后闭嘴"）：认一句＋改，**改完就停，不连发解释**。
- 与用户偏好「介意 AI 感」同源：对方高敏、介意"被分析／被套路"，消息一旦有机器感／说明书感，立刻触发防御。表达质感是规避 AI 感的**第一道防线**。

### 低效话术（成功率低，默认不用；有明确理由时可说明为何要用）

| 话术 | 为什么低效 |
|---|---|
| 逼迫表态（「你到底喜不喜欢我」「给个准话」） | 把对方逼到必须拒绝的位置，且答案不可信 |
| 付出陈述（「我为你做了这么多」） | 触发防御，把讨论从感受转成算账 |
| 自我贬低换取安慰 | 短期有效，长期把关系变成安抚义务 |
| 群发式通用情话 | 一眼假，反而降低信任 |
| 涉及外貌/身体的评价 | 关系未明确时会被读作轻浮或冒犯 |

## 五、动机护栏（健康原则 + R1/R2/R3 红线）

> 本集是狗头军师的**动机层护栏**，与三军规的话术层纪律互补：话术层管「怎么说」（点射 / 留白 / 无时差），动机层管「什么动机不能说」（push-pull 冷热 / 高位打压 / 广撒网暗示）。
>
> 以下三条是已存在于原逻辑的健康原则（情绪稳定 / 有自己生活 / 节奏校准），统一成可执行规则；拒绝项写成红线，生成任何话术 / 行动前强制过一遍。
>
> 立场：不套博弈 / 高位低位框架，先用指标核验。任何把博弈框架作为主引擎引入 skill 的设想一律否决。

### 情绪合法性（元原则——先说清楚，再谈拦截）

> **情绪不在本 skill 的管辖范围。被拦截的从来只是动作，不是情绪。**

- 感到委屈、生气、不甘、被冷落——都是正常人的正常反应，**不构成违规、也不需要被纠正**。连续拦截用户的提案时，容易让人误以为「我连有情绪都被管」——这是**表述问题，不是规则问题**：本集管的是「拿这份情绪去驱动了什么动作」。
- **判定分界（关键）**：
  - 生气 → 想骂她 / 想冷她几天 / 想虚构理由让她也难受 ＝ **动作**，受红线管辖。
  - 生气 → 出去跟朋友吃一顿 / 运动 / 忙自己的事 / 发一条中性朋友圈 ＝ **情绪出口**，合法且应当被鼓励。
- **情绪的正确出口清单**（优于在对话内消化）：① 真实生活转移（朋友局 / 运动 / 自己的事）；② 延后处理（气头上不发任何消息）；③ 向第三方倾诉（不是向对方，也不是向共同熟人）。
  **禁止的出口**：向对方发泄；策略性冷处理；**把情绪伪装成「策略」再执行**——最后这条最危险，因为它表面像理性决策，实则是情绪报复穿了件战术外套。
- **给分析者的话术要求**：用户表达情绪时，**先承认情绪合理，再判动作**。不得把「你有情绪」当作需要纠正的对象；也不得因用户正处在情绪中，就预设其提案必然违规——仍须按动作实质逐条判，该放行的要放行。
- **疏导纪律（拦截 ≠ 指责）**：拦截一个动作的同时，必须**疏导它背后的动机**——用户为什么会想这么做（被冷落的委屈 / 想被重视 / 想拿回主动权 / 想证明自己不是随叫随到 / 想确认对方是认真的）。**先命名这个诉求并明确确认它合理**，再说「为什么这个具体动作达不到它」，最后给「哪条路径能真正达到」。
  **禁止只输出「这违规 / 这不行」**——那只会让用户觉得被管，且会把合理诉求连同动作一起否定掉；后果是用户下次绕过 skill 直接行动，护栏形同虚设。实测对照：用户「制造落差 / 立规矩」的背后是**完全合理**的诉求「我的时间也有价值、不想被随叫随到」——命名并确认它之后，方案自然转向「自律 + 真实忙碌」，用户当场接受；而只讲拦截时，同一诉求被反复包装成新提案，连撞四轮红线。
  **顺序固定：情绪 → 诉求 → 动作判定 → 合法替代。** 前三步缺任何一步，第四步都会被当成说教。
- **连续拦截时的沟通纪律**：对**同一用户的提案连续拦截 ≥ 2 次**时，必须先申明一句「**拦的是动作，不是你这个人、也不是你的情绪**」，并**逐条列出提案中通过的部分**。实测：这类提案绝大多数是「**前半合法、后半违规**」的混合物（如「17 点开个轻话题」合法 +「为制造落差而回绝」违规），全盘否定会让用户感到被管死，也会一起埋掉本可执行的那一半。**每次拦截必须附合法替代路径**，不得只给否定结论。

### 需求疏导优先于手段判定（拦截 ≠ 指责）

> 用户提出的**每一个被拦截的动作，背后都有一个正当需求**。判动作之前，先把那个需求找出来、命名、肯定——**再判手段**。只判手段不疏导＝指责，会让人觉得自己的感受连同诉求一起被否掉。

- **拦截时必须走完的四步**（不得从情绪直接跳到判定）：
  1. **接住情绪**——承认这份情绪合理（见上条）。
  2. **提取并命名需求**——这个动作想满足什么？常见正当需求：想被重视 / 想要确定性 / 「我的时间也有价值」/ 不想被随叫随到 / 想被平等对待 / 想确认对方在乎 / 想拿回主动权。
  3. **肯定需求本身**——该需求**正当且可实现**，不得用「你想多了 / 别钻牛角尖 / 她不是那样的人」打发掉，也不得把用户的诉求改写成更轻的版本再判（＝偷换需求）。
  4. **才判手段**——问一句：**这个动作真能满足它命名的那个需求吗？** 多数情况下**不能**：惩罚性拒绝带不出「被重视」，虚构忙碌带不出「我的时间有价值」（反而砸信任维），制造落差带不出「确定性」（反而制造更多不确定）。判完立即给**能满足同一需求的合法路径**。

- **禁止的三种指责式输出**：① 只输出「这样会命中 R1 / R3」而不提取需求；② 用「你想多了」否定感受；③ 连续判定而不留疏导位——让用户觉得每一句话都在被审。

- **本轮实例（可作范式）**：用户诉求「我的时间也有价值 / 不想被随叫随到 / 约我要提前」→ **需求完全正当**；被拦的只是**手段**（虚构理由 / 惩罚性回绝 / 为制造落差而拒绝）。合法路径＝**自律 + 真实忙碌 + 用示范立规**（自己发出「明确时间 + 明确地点 + 可无痛拒绝」的邀约，由格式带出对方行为——示范改变行为，拒绝只制造痛感）。

### 三条健康原则（已以健康形态存在，统一成规则）

**A. 情绪稳定性（对应「不舔 / 不被带跑」）**
- 规则：对方焦虑 / 冷淡时，**不追加解释、不求证、不提速**，维持自身低频、日常、友好的状态。
- 触发：检测到对方 `momentum_recent_vs_base` 下滑 / 出现焦虑措辞（「你是不是…」「怎么不回」）/ 你产生「要证明自己」冲动时。
- 已有体现：9/24 收手纪律（发完末条零动作）、三档话术「保守」档。
- 判定边界：本条 ≠ 「故意冷处理」。冷处理是策略性沉默（push-pull，见红线 R1），情绪稳定是**自然不慌**——前者算红线，后者算原则。

**B. 自有生活展示（对应「有自己生活、在场但不黏」）**
- 规则：分享你自己的日常 / 事业 / 兴趣，**作为生活状态的自然呈现**，不炫耀、不邀功、不暗示「很多人围绕我」。
- 触发：会话出现空洞或你想起「要不要表现一下」时，转向真实生活切片（面料工厂、运动、朋友局），而非表演。
- 已有体现：清峰 9/24 自评「优势要有自己生活」。
- 判定边界：展示 ≠ 社交证明炫耀（晒车 / 局 / 异性缘）。后者踩红线 R2。另一条边界：**展示是行为，不是宣言**——用真实安排说话（「今晚在加班走不开，明晚行吗」），不用「我也挺忙的，不是随叫随到的」这类宣告；宣告＝框架压制，踩 R3 边缘。第三条边界：**晒生活可以，但先过「刺痛元素清单」**。刺痛源不是「发不发」，而是内容里有没有这三类元素：① **浪漫 / 双人向场景**（夜景、烛光、情侣向场所）；② **异性陪伴对象**（合照出现异性、亲密构图）——对高焦虑 + 已有专一约定的一方会触发「他是不是还有别人」；③ **指向对方的暗梗 / 对照句 / 宣告文案**（「一个人也挺好」「不缺陪伴」等）。朋友局 / 哥们局 / 探店 / 工作日常属**正常生活切片，可发**；被问到如实说，不渲染。
   - **场景分级**：公开渠道（朋友圈 / 动态）比私聊宽松——它是生活记录，不是定向输出，不构成施压；私聊里主动抛给对方则仍受「不主动晒」约束。**同一家店会因业态改变判定**：浪漫茶院禁晒，烧烤夜宵院（哥们局）可晒——先核实业态再判。
   - **动机自查（硬）**：为**记录生活**而发＝合法；为**「让她看到 / 让她有落差 / 让她知道我不随叫随到」**而发＝ R1（制造痛感）。二者的外在行为完全一样，区别只在发之前的那一念。

**C. 节奏校准（对应「不黏不逼、节奏由关系状态决定」）**
- 规则：**节奏由关系状态决定，不由战术决定**。对方快你别慌，对方慢你别冲；永远不处在让对方需表态的位置。
- 触发：要发邀约 / 推进时先问「这条发完，她有没有无痛说『不』的空间？」——没有就降级或改天。
- 已有体现：9/25 三选一正式邀约逼出她「开玩笑啦」降回 → 已验证「逆向校准」比快推进更准（童锦程快推进，你们逆向）。
- 判定边界：校准 ≠ 拖延迟迟不推进。暧昧后期需要一次明确、可拒的邀约（见三 · 常见情形），静止不动同样违规。

### 三条红线（动机层禁用，对本关系为毒性，强制禁用）

| 红线 | 禁用动作 | 为什么对本关系有毒（证据） | 触发即拦截 |
|---|---|---|---|
| **R1 · 禁 push-pull / 冷热交替** | 故意冷处理、制造不确定性、欲擒故纵，包括“热一天冷两天”、故意晚回和策略性失联 | 柒月 = 高焦虑型（9/24 坐实）；9/25 她主动往前冲要确定性。冷热交替 = 把她推进「他是不是不爱我」的坑，拆刚坐实的机制 | 话术含「故意隔很久回」「先不理她」「吊着」「让她猜我喜不喜欢」等意图 → 拦截改写 |
| **R2 · 禁 abundance / 广撒网话术** | 暗示换人成本低、展示其他异性选项、虚构追求者或营造“不缺女人/男人” | 9/15 约定彼此唯一、认真一个月；柒月「专一」是信任核心（信任维 92）。违反协议且直接伤信任 | 任何「我又不是没人要」「多的是人」「让她知道我有选择」类暗示 → 拦截 |
| **R3 · 禁高位打压 / 框架压制** | 用「谁高位谁赢」「征服」「慕强」姿态，贬低对方需求或把互动当权力游戏 | 高位低位框架已核验不适合（差异在表达密度不在权力）；柒月高焦虑，打压 = 触发防御 / 退缩 | 话术带居高临下、评判对方「作 / 闹 / 就得被征服」 → 拦截改写 |
| **R4 · 渐进影响纪律（目的可给 / 极左极右速决禁出 / 按性格定制 / 禁马上断联）** | 见下「R4 细则」 | 柒月 = 高焦虑 + 已约定专一；本关系靠"影响"推进，不靠"断裂"倒逼 | 方案开头即给断联 / 冷处理 / 高频加码 / 压迫推进 → 改回"最终目的 → 渐进步骤" |

### R4 细则 · 渐进影响纪律（策略输出层，约束"怎么给方案 / 怎么做决策"）

> 这是**比 R1/R2/R3 更高一层**的纪律：R1–R3 管"单条话术的红线"，R4 管"整体方案与决策的出口形态"——约束的是**你给用户的方案长什么样**，不是某一句话。

1. **目的与手段分层（极左极右速决禁出）**：可以给"最终要达到的目的"，但**禁止在方案开头就输出极左（断联 / 冷处理 / 彻底抽离 / 消失）或极右（高频加码 / 情绪轰炸 / 压迫式推进）的速决手段**。所有可执行手段必须落在**中间渐进带**——先给观察与轻量动作，再视对方反应升级，且每一步都要过 G3 耐受拷问（最坏情况你接得住吗）。

2. **性格定制约束**：任何行动方案与话术必须**锚定对方已确认的性格特征**推导，禁止给脱离性格的通用模板。本次锚点：柒月＝高焦虑（需确定性、反刍放大）、公开场合缩 / 私密才放、已约定专一。凡方案未写明"这是针对她哪条性格特征"的，视为未过检。

3. **禁止马上断联（关系靠影响，不靠断裂）**：决策输出**不得把"立刻断联 / 消失 / 冷处理"作为解法**。人与人的关系改变靠**持续影响**而非断裂——断联只是把问题冻结，不解决也不推进。因此方案结构必须是：**最终目的 → 分阶段步骤（每步可观测、可回退）**，让影响在过程中发生，而不是靠切断来"逼"出结果。

### 红线伪装识别（用户常用来包装红线的说法，一律按原红线拦截）

博弈动作很少以本名出现，通常以「合理诉求」的面目提出。以下说法命中即按对应红线拦截，**不看措辞只看动作实质**：

| 伪装说法 | 实质动作 | 命中红线 |
|---|---|---|
| 「让他也有落差感」「让他体验一下被晾」 | 人为制造不确定性 / 痛感 | R1 |
| 「先不理他，等他来找我」「刷一波就走」 | 策略性沉默 + 扫射后抽身 | R1 + 军规1（只点射） |
| 「立规矩：约我要提前」「让他知道我不是随叫随到」 | 以拒绝/惩罚纠正对方 | R3 |
| 「这是对等的」「我也要让他尝尝」 | 把互动当记账与权力博弈 | R3 |
| 「我故意说我有安排了（其实没有）」 | 虚构 scarcity 制造竞争感 | R1 + R2 |
| 「先冷他两天，他就会主动」 | 欲擒故纵 | R1 |
| 「热一天冷两天，让他猜不透」 | 计划性冷热与间歇性奖励 | R1 |
| 「让他知道我不缺异性」 | 制造竞争与稀缺 | R2 |
| 「对方就得被征服 / 只慕强」 | 性别刻板印象 + 框架压制 | R3 |

**拦截时的回应方式**：不否定其**诉求本身**（想要确定性、不想被临时放鸽子、希望投入对等——都是合理诉求），只否定**手段**；并给出合法替代路径（见下）。

**合法替代（诉求可达，但不动机干净）**
- 想要「确定性 / 提前约」→ **用示范立规，不用惩罚立规**：你自己发出明确时间 + 明确地点 + 提前量的邀约，且可无痛拒绝。对方照做是被你的格式带出来的，不是被你的拒绝吓出来的。
- 想要「对等」→ **降自己的量**（留白 50%、收手纪律），而不是**制造对方的痛**。对等是收自己的，不是讨对方的。陈述时用**平行句**不用**对照句**：✅「我今晚也约了朋友」（平行，各自有生活）｜❌「你跟朋友玩，那我也约朋友」（对照＝记账＝R3）。
- 想要「不被随叫随到」→ **真实忙碌**（你确实有事就说有事），不是**虚构忙碌**（没安排却说有安排）。前者是生活，后者是战术。
- 需要拒绝某一次具体邀约 → **真实理由 + 反提**（「今晚已经有安排了，明晚 / 周末行吗？」）。**纯拒绝**（只说不行、不给替代）＝ R1：把球打死、制造不确定性；**虚构理由**＝ R1 + R2：一旦被拆穿直接砸信任维。区别只在**有没有反提**与**理由真不真**。
- 想要「提前约」→ **立给自己，不立给对方**：我发起的邀约一律给出**明确时间 + 提前量 + 可无痛拒绝**（自律项，合法）；对方没提前就回绝＝惩罚项，命中 R3。示范能带出对方的格式，拒绝带不出——前者改变行为，后者只制造痛感。
  - **例外（防止规则僵化）**：对方在**当下对话中主动递话**（「好无聊」「突然想吃 XX」「今晚没事」）时，可顺势接住并提出，**不须守提前量**——这属于**接球**，不是冷启动式临时邀约（发起）。规则约束的是「发起」，不是「接球」；高焦虑型递话时你不接，会被读成拒绝。
  - **前提（归因纪律）**：提前量只在对方**可用状态**下才有效。对方异地 / 已有安排 / 恢复期时，提前 1 天与提前 3 天一样无效——先核可用性，再谈提前量。

### 人设 / 身份标签类包装（与 R1 / R3 同源，一并拦截）

用「我是某种人」包装动作时，动机容易**从事实滑向表演**。以下标签均属「用姿态定义自己」而非「用关系定义自己」，命中即提示风险：

| 标签 | 包装的动作 | 风险 |
|---|---|---|
| **「西格玛男人 / sigma」** | 不围着对方转、专注自己的事 | 内核＝「不需要任何人」（独狼），与**专一约定**直接冲突；且易滑成「为维持人设而拒绝本可赴的约」＝虚构忙碌（R1 + R2） |
| 「高价值人设 / 框架控制」 | 用姿态而非事实吸引 | 同博弈外壳，已整体否决 |
| 「高位 / 谁高位谁赢」 | 把互动当权力游戏 | R3 |

**判定法（去掉标签看动作是否仍成立）**
- 「我今天加班走不开」——去掉任何标签仍成立（事实）→ **合法**
- 「我是西格玛，所以我不去」——去掉标签后动作失去依据（表演）→ **拦截**

**正确自我描述**：是「我有自己的节奏 / 我确实忙」，不是「我是某种人」。前者**容纳亲密**（忙完就去），后者**拒绝亲密**（独狼不需要任何人）。

### 与既有框架的关系
- 与「三档话术」「三条实战铁律」互补：铁律管话术层「怎么说」（点射 / 留白 / 无时差），本集管动机层护栏——禁 push-pull 冷热、禁高位打压、禁广撒网暗示。
- **自检**：生成任何话术前，先过 R1 / R2 / R3 / R4 四条护栏，并过「红线伪装识别」表（按动作实质判定，不按措辞）；任一命中即重写，且**不向用户隐瞒**——注明「已按红线拦截某动作」，同时给出上表「合法替代」中的对应路径。R4 专项：方案是否给了**最终目的 + 分阶段步骤**、是否**按对方性格定制**、决策里**有没有把"马上断联 / 冷处理"当解法**——有即拦截改写。

### 适用边界
- 本红线针对**已确认专一、对方高焦虑的亲密关系**。若未来分析对象是初识 / 非排他场景，R2 的「禁 abundance」可放宽（但仍不建议欺骗），R1 的「禁冷热」仍需谨慎（高焦虑者通用）。
- 任何把博弈框架作为主引擎引入 skill 的设想，一律否决——本集只守原逻辑的健康原则，不引入任何博弈外壳。

## 六、心态波段分析法（逐句扫描层 · 三个方法的共同前置）

> **用户口径**：VOL / 差评好评 / 异动分析，**都是用户上传记录之后，先把聊天记录逐句扫一遍，再聚合、再总结**——找出变化、背后原因、应对方法。本节规定这个"逐句扫描"怎么做，其输出是后面三节的输入。

### 它回答什么
她在**哪些时间点**心态升高、哪些时间点回落／防御／抗拒／同意／热忱；**升级的地方在哪、降的地方在哪**；每个拐点前你说了什么（触发句）；因此该怎么应对。

### 标签体系（8 类）

| 标签 | 分值 | 含义 | 典型 |
|---|---|---|---|
| **热忱** enthusiasm | +2 | 主动投入、热情 | 哈哈／期待／爱你／主动发图／连发 |
| **同意** agreement | +1 | 接受、配合 | 好的／可以／你定／行 |
| **中性** neutral | 0 | 信息交换 | 陈述 |
| **试探** probe | 0 | 间接索取确认 | 是不是／应该…的／你觉得呢 |
| **脆弱** vulnerable | −1 | **开放信号（需接住）** | 累／难过／失眠／压力大 |
| **防御** defensive | −1 | 解释、撇清 | 不是／哪有／开玩笑啦 |
| **回避** avoidance | −1 | 敷衍、转移 | 嗯／哦／随便／忙 |
| **抗拒** resistance | −2 | 明确拒绝 | 不行／算了／改天／不用 |

> **关键区分**：`脆弱` **不是负面**——它是开放信号，接住会升温，漏掉才变冷；`抗拒` 才是否定。把脆弱读成冷淡，是本方法最常犯的错误。

### 方法（五步）
1. **逐句标注**：只对**对方**的消息打标签；**自己的消息保留用于归因**。
2. **平滑**：滚动窗口（默认 5 条）均值 = trend，消除单句抖动。
3. **波段**：**按日聚合后再切段**（逐句分段会碎片化到 80+ 段，不可用）。level：≥0.6 升温段／≤−0.4 回落段／其余平台段。
4. **升降点**：跨窗口比较（当前 vs window 条之前），|delta| ≥ 1.0 记候选，取**局部极值 Top N**；**每处必附触发句**——该点之前最近一条你自己发的消息。
5. **归因与应对**：升温点 → 记下**可复用动作**（以后多做）；降温点 → 写清"当时该说什么"，并查触发句属于哪类动作（加压／加码／自嘲／分享／说教／差评／邀约）。

### 输出要求
- 必须给出：**波段清单**（含趋势值与样本量）、**Top 升温点**、**Top 降温点**（各含触发句）、每日标签分布。
- **必须声明启发式性质**：词典标注是近似，关键句需人工复核，不得把标注当事实断言。
- 波段结论须与 **VOL（事件窗）**、**异动（维度漂移）**交叉验证；三者冲突时，**以人工复核的原文为准**。

### ★ 结合人物性格滤镜（同一标签，不同性格含义不同）

波段标签**不是普适结论**，必须套回对方已确认的性格读：
- **回避 / 防御**：在**高焦虑型**身上，回避常是「安全感测试 / 黏着犹豫」而非「冷漠抽离」——她可能同时条数没降、时延没升（见 VOL 焦虑峰值）。误读成"她冷了"会触发你过度补话，反而把她推远。**判据：看时延 + 看条数，二者没变就不是抽离**。
- **脆弱**：是开放信号，**所有性格都要接住**，但高焦虑者更敏感——漏接一次会被反刍放大成一整天的"他是不是不在乎我"。接住动作要更及时、更具体（点名她的状态，不泛泛"怎么了"）。
- **热忱 / 同意**：低表达密度型（句短、回应率高）的"同意"已是高投入信号，别拿高表达密度型的标准去要求她"更热"。

> 用法：每个升降点的"应对"都要回一句「针对她{X}性格，该做/不该做」。未挂性格的应对视为未过检（配合 persona-engine 第 4 条硬规则）。

### 工具
`scripts/band_analysis.py <chat.txt> --self <本人> --other <对方> [--window 5]` → `band.json`（逐句时间轴／日序列／波段／升降点／每日分布）。

## 七、VOL（心态波动率）分析：突发事件下的心态响应

> **前置（硬要求）**：事件锚点**不许凭印象挑**——必须先跑第六节「心态波段分析法」的逐句扫描，从时间轴与升降点里挑出真正的事件（优先取**降温点与升温点所在时间**及其前后句），再进本节的窗计算。
> **VOL 也是逐句读**：窗算完之后必须回到窗内**每一句原文**复核方向，指标与原文冲突时**以原文为准**。统一入口已输出冲击窗内的波段标签分布（`shock_label_dist`）供逐句复核。
> **自动锚点＝候选不是结论**：用 `analyze_all.py` 不传 `--events` 时，事件锚点自动取自波段升降点，此时会混入低量日噪声（实测：低量日「量降＋时延升」会被误判成「抽离」）。凡 `needs_confirm: true` 的事件，**人工确认为真事件后才采信**；危险型（抽离）结论只采信确认过的事件。

> **命名消歧（必读）**：`volume_skew`＝**量能偏斜**（静态：谁的字数多）；**VOL＝Volatility（心态波动率）**（动态：事件冲击 → 偏离 → 回归）。二者同名缩写易混，用户说「VOL」默认指**心态波动率**。scripts 里的 `VOLUME_SKEW` 信号属前者，**不是**本节所指。

**它回答什么**：静态指标（volume_skew / initiative_skew）只能说明「平时谁投入多」，回答不了「**出事时她会怎样**」。VOL 回答：遇到突发事件，她是**向热还是向冷**、振幅多大、多久恢复、**会不会外逃**。

### 方法（三窗）
0. **工具**：`scripts/vol_analysis.py`（三窗法自动算），用法 `python vol_analysis.py <chat.txt> --self <本人> --other <对方>`，输出 `vol_daily.json` / `vol_events.json`。脚本内 `EVENTS` 清单需按案例替换（默认示例为清峰×柒月的 7 个事件）。
1. **事件锚点**：从记录中标注突发事件——自我暴露 / 关系定义冲击 / 承诺约定 / 焦虑表达 / 身体或行程压力 / 安排冲突 / 线下见面。**来源＝第六节逐句扫描的升降点时间轴**。
2. **基线**：事件前 14 天的日均指标（不足则取全周期日均，并注明）。
3. **冲击窗**：事件当日 + 次日；**恢复窗**：事件后 2–4 天。数据不足（事件落在记录末尾）须标注「数据不足」，**不得外推**。
4. **逐句复核**：窗算完之后，回到**该窗内的每一句原文**复核方向（向热/缩量/抽离），指标与原文冲突时**以原文为准**。

### 观测维度（均取 冲击 ÷ 基线）
`msg`（条数）、`char`（字数）、`q`（提问）、`pos`（正向词）、`neg`（负向词）、`hedge`（闪烁词：应该/可能/再说）、`low`（低投入语）、**`latency`（回复时延中位数）**、**波段标签分布**（第六节 8 类标签在该窗内的占比，尤其脆弱 / 防御 / 回避 / 抗拒）。

### 判读规则
- **向热（安全型波动）**：量↑ + 提问↑ + 时延持平或↓ → 冲击让她更黏，不作处置。
- **缩量（压力型）**：量↓ + 负向词↑ + **时延不升** → 有压力但**不抽离**；处置＝**减压**（短、轻、可拒），禁止追问。
- **抽离（危险型）**：量↓ + **时延↑** + 提问↓ + 出现长静默 → 撤退信号；处置＝给空间 + 不补枪，并做一次可证伪检验。
- **判读金标准**：**看时延，不看字数**。量降不代表冷，**时延升才是冷**。

### 典型模式（可复用）
- **承诺后焦虑**：承诺类事件（约定专一 / 定义关系）后 `hedge` 闪烁词暴增、恢复窗 `neg` 上升 → 她在担心能否兑现。此时**禁止继续加码定义推进**，改用**行动稳定兑现**（守约、稳定出现、不加新要求）。
- **见面后回落**：线下见面后 2–4 天线上量降、`neg` 上升 → 见面后有回落期。**禁止在此时追问下次见面／推进肢体**，给 2–4 天缓冲，等她自然恢复。
- **压力缩量**：身体 / 行程压力下量降但时延不变 → 只缩减表达，不抽离；短关心即可，不接管、不照料。
- **焦虑峰值**：负向词↑ + 时延↑ 但条数不降 → 「黏着犹豫」而非「抽离」，处置＝明确稳定的回应，不要追问「你怎么了」。

### 输出要求
必须给出：基线 / 冲击 / 振幅 / 恢复窗 / **方向判定** / **对应处置动作**；并说明是否有长静默（外逃性）。

### ★ 结合人物性格滤镜（同一 VOL 模式，性格不同处置不同）

- **缩量（压力型）**：在高焦虑者身上，**缩量极易被误读成抽离**——但金标准看时延。若她量降、时延不升、提问没降，那是"有压力但不抽离"，处置＝减压（短、轻、可拒），**禁止追问、禁止补话**。对低焦虑者同样信号可能只是忙，处置更轻。
- **抽离（危险型）**：高焦虑者的"抽离"往往伴随**反刍**——她不是不回，是反复想"他是不是变了"才回得更慢。此时给空间 ≠ 消失，**给空间但要留一个稳定的低压力存在信号**（一条日常分享即可），否则她会把静默读成"被放弃"。
- **承诺后焦虑**：高焦虑者最典型的 VOL 模式（约定专一后闪烁词暴增）。低焦虑者约定后通常平稳。→ 高焦虑者约定后**禁止加码定义推进**，改用行动稳定兑现；低焦虑者约定后可自然推进。
- **焦虑峰值**（负向↑+时延↑+条数不降）：这是高焦虑者专属形态，本质是"黏着犹豫"，处置＝明确稳定的回应，不要追问"你怎么了"（追问＝把她推去反复想）。

> 用法：每个事件的"对应处置动作"必须注明「针对她{X}性格」。默认不写性格的，按高焦虑假设落处置——但若画像未确认焦虑水平，须先补画像再下处置。

## 八、差评/好评分析法（吐槽 / 负面评价 / 直白批评 / 强要要求 ＋ 表扬肯定）：风险点与应对

> **方法名与分工（用户口径，勿混）**：
> - **第八节＝差评/好评分析法**＝**单次表达层**的逐句识别（负向的吐槽／负面评价／直白批评／强要要求，正向的表扬／肯定／示好），管"这一句话该怎么说、说了会怎样"。
> - **第九节＝异动分析法**＝**长期维度层**的漂移（价值观／三观／性格／兴趣／谈话风格），管"她这个人最近往哪变"。
> - **第七节＝VOL**＝**突发事件层**的短窗波动。三者逐层嵌套，**互不覆盖**。

> **前置（硬要求）**：本节所有正负向表达，**必须来自第六节「心态波段分析法」的逐句扫描结果**——先给聊天记录每一句打上标签（热忱/同意/中性/试探/脆弱/防御/回避/抗拒），再从标注结果里挑出指向对方的负向句与正向句，**不许凭印象挑句子**。

> **定义 · 差评侧**：凡**指向对方**的负向输出都属此类——吐槽她的行为、负面评价她的选择／习惯／状态、直白批评（含"点一下"式的提醒）、以及**命令／强要式索取**（"你必须""发我一张""你说清楚"）。
> **定义 · 好评侧**：凡**指向对方**的正向输出——表扬、肯定、夸奖、感谢、示好、明确喜欢（"你今天这个很好看""有你在真好""爱你哟"）。
> **不属于此类（安全区）**：自嘲自黑、吐槽第三方或环境（工作、天气、店）、陈述自己的感受。

### 为什么要单独成节
差评类是**唯一一类"说得越真越危险"**的表达。它往往出于真实感受（你确实不满、确实想被重视、确实想立边界），所以最容易被自己当成"我不过是说实话"而放行。但对**高焦虑型 + 考察期**的关系，它触发的不是"被提醒"，是**"被否定"**。

### 技术风险点 TR（每条都挂着既有规则，可追溯）

| TR | 机制 | 命中的既有规则 |
|---|---|---|
| **TR1 喂给核验系统** | 她在反复核验"他这里安不安全"（例：她自述失眠"在想你到底是个什么样的人"）。差评＝给这个系统投一份**否定证据**，且高焦虑型会**反刍放大** | 考察期风险清单 |
| **TR2 评价＝审判位** | 关心与反馈要用**问 / 听**，不用**评价**（医美线教训） | 既有教训 |
| **TR3 剥夺无痛拒绝** | 命令式索取没有"不行"的位置 | **不处表态位**（战术纪律） |
| **TR4 玩笑包装不豁免** | 幽默外壳下的评价，高焦虑型会**剥壳**读到批评本身 | 不处表态位的精神 |
| **TR5 时序叠加** | 落在她的**压力窗 / 见面后回落窗 / 承诺后焦虑窗**内＝叠伤 | **VOL 第七节**处置规则 |
| **TR6 人格化笼统** | "你总是""你就是这种人"——最毒。它调用的是她**旧关系里被否定的模式**（自述前夫相关创伤），触发的是旧伤不是这件事 | 高危信号 |
| **TR7 负向表达累积** | 单条影响有限，重复且缺乏修复时风险上升；`pos_neg_ratio` 只作窗口描述，不作健康阈值 | 描述指标 + 人工复核 |
| **TR8 补枪放大** | 发完撤回／解释／追问"你是不是生气了"→ 二次伤害＋需求感暴露 | **收手纪律 / 偶发冷场不补枪** |
| **TR9 撤回否认** | "我开玩笑的"把已说出的评价变成**不确定源**，等同小型 push-pull | **R1** |
| **TR10 场域放大** | 群聊／朋友圈／有他人在场，伤害按公开程度平方放大 | **R3** 边缘 |

### 判读分界：什么算，什么不算

- ❌ **指向她的评价**：你今天怎么这么慢 ／ 你每次都这样 ／ 你这样不行
- ❌ **命令式**：发张照片 ／ 你必须 ／ 你给我说清楚
- ✅ **指向自己的感受**：我有点着急 ／ 没收到回复我容易瞎想
- ✅ **自嘲／吐槽环境**：我今天笨死了 ／ 这破店太吵
- ✅ **具体一次行为＋影响＋台阶**：上次那条我没接到，有点失落，下次晚点回我一句就行

### 应对 A（与 TR 对应）

- **A1 感受陈述替代评价**：说"我"，不说"你"（对应 TR1/TR2）。
- **A2 具体行为替代人格**：只说**这一次**，绝不上升到"你这个人"（对应 TR6）。
- **A3 请求替代命令**：命令 → **可拒的请求**（明确＋可以不行）（对应 TR3）。
- **A4 互动背景**：反馈前检查近期是否只有负向、是否有真实肯定与修复；`pos_neg_ratio` 只作窗口描述，不执行固定 `5:1` 或每周次数纪律（对应 TR7）。
- **A5 时序门控**：她的压力窗、见面后回落窗、承诺后焦虑窗内，**一律不发**差评（对应 TR5）。
- **A6 三句式反馈**（真需要反馈时）：**具体行为 → 对我的影响 → 给她台阶**；不评价动机、不上升人格（对应 TR2/TR6）。
- **A7 发出之后**：**不撤回、不解释、不追问**——补枪比原话更伤（对应 TR8）。若明显伤到，允许**一句**简短修复（"刚才那句说重了"）；**修复 ≠ 补枪**：一次性、不解释动机、不求原谅、说完就停（对应 TR8/TR9）。
- **A8 场域**：任何差评**只走私聊**，不走群、不走朋友圈、不当众（对应 TR10）。

### 接收侧：她发差评给你时怎么读

- 焦虑、试探性求安抚、具体不满或攻击都可能产生负面表达；先按字面、诉求、语境和边界区分，不按依恋标签预判。
- **判读三问**：① 有没有**具体诉求**？② 有没有**反提**（给了替代方案）？③ 是不是落在她的**压力窗**内？
- **应对**：接住情绪（不先复述事实）→ 给一个**具体回应** → 不辩论、不反击、**绝不冷处理（R1）**。
- 她若直白批评你：先接住、不辩解；需要澄清的**事后一句**，不在当下对账。

---

### 好评侧：表扬 / 肯定（同一个天平的另一头）

> 好评不是差评的反面教材，是**独立的工具**——用错了同样伤关系，只是伤得更隐蔽。逐句扫描里标为「热忱／同意」的句子，进本节二次判读。

#### 好评的技术风险点 PR

| PR | 机制 | 说明 |
|---|---|---|
| **PR1 空泛赞美失效** | "你好美""你真棒"无具体锚点 → 高焦虑型读成**客套**，甚至读成"他没真的在看我" | 赞美必须挂**具体事实** |
| **PR2 密度与动机错位** | 集中赞美可能让对方感到压力或像在换取回应 | 结合语境与对方反馈调整，不人为制造稀缺 |
| **PR3 评价位陷阱** | 夸"你很懂事／很会照顾人"＝**给她定角色**，本质是评价（TR2 的正向版），她会有"要一直符合"的压力 | 夸**行为与感受**，不夸**人格角色** |
| **PR4 公开场域加倍** | 朋友圈／群里夸＝把她放到被围观的位置（她公开场合缩、私密才放得开） | 走私聊 |
| **PR5 术后 / 压力期踩点** | 她刚做完医美、正在忌口难受时夸"变漂亮了"＝**提醒她在恢复期**，且暗含"我在评判你的脸" | 时序同样门控 |
| **PR6 与差评配比失衡** | 好评在差评前后集中投放 = 被读成"铺垫"（要提要求了） | 见 A4 配比 |
| **PR7 夸完立刻索取** | "你今天真好看，发张自拍呗" → 前面的夸全部作废，变成交易 | 好评与请求**分离** |

#### 好评的应对 G

- **G1 具体锚点**：夸**这一次的具体事实**（"你刚才那句把我逗笑了"／"你选的那家店真不错"），不夸抽象特质。
- **G2 夸行为不夸角色**：❌"你真懂事" ✅"你刚才那样处理，我觉得挺舒服"。
- **G3 频次**：以真实、具体和对方可接受为准，不设日均次数；赞美与索取分开，避免形成交易压力（PR7）。
- **G4 走私聊**（PR4），压力窗／术后恢复窗内只夸**行为与陪伴**，不夸外貌（PR5）。
- **G5 背景**：用持续的尊重、肯定与修复形成正向背景；不按固定比例或 24 小时窗口机械安排赞美（PR6）。
- **G6 接住她的好评**：她夸你时，**接住 + 回指具体**（"你这么说我挺高兴的，那我下次还这么干"），不自贬、不反问"真的吗"（自贬＝变相索取确认）。

#### 工具
`scripts/praise_blame_scan.py <chat.txt> --self <本人> --other <对方>` → `pb.json`（我方差评/好评清单、接收侧清单、正负比、纯媒体分享计数）。
**误报过滤条（BLAME_SAFE / PRAISE_SAFE）**：「不好意思」「你又不是」等客套玩笑不判差评；偏好提问（「喜欢…还是讨厌…」）不判差评；好评必须含「你/咱/我们」＝**指向对方**，否则只是自己的正向情绪；纯媒体行计为 share 不计好评。
**硬要求**：脚本只出**候选清单**，**必须人工复核后再下结论**（实测：8 条差评候选复核后真实差评仅 1–2 处）。

#### 好评的可用时机（正面清单）
她**主动分享**之后（图／日常／工作成果）→ 立刻具体夸；她**脆弱表达被接住**之后 → 夸她的坦诚（"你愿意跟我说这个，我挺高兴"）；**线下见面后 2–4 天回落期** → 夸见面里的具体瞬间（此时正向最值钱，正好对冲回落）。

### ★ 结合人物性格滤镜（差评/好评因性格放大或失效）

- **差评触发「被否定」而非「被提醒」**：这是**高焦虑型**的核心机制（见「为什么要单独成节」）。对高焦虑者，一句差评会被**反刍放大成一整天的安心缺失**——直接对应 persona-engine 的「性格缺点 / 雷区」。→ 差评必须过 TR 五道闸，且**绝对避开她的雷区触发条件**（例：她需确定性，差评＝确定性缺口）。
- **好评失效形态随性格变**：高焦虑者把空泛赞美读成"客套／没真看我"（PR1）、把公开夸读成"被围观"（PR4，结合她"公开场合缩、私密才放"）。→ 好评必须挂具体事实、走私聊。低焦虑者同样好评可能被正常接收为鼓励，处置可更轻——但**默认按高焦虑落处置**，除非画像已确认低焦虑。
- **接收侧（她发差评给你）**：高焦虑者发差评常是"要确定性"（"你到底怎么想"的变形），不是攻击——接住＝给明确稳定回应；低焦虑者发差评更可能是真不满。误判她的差评动机＝错配应对。

> 用法：每条差评/好评候选的"整改形态 / 可用时机"必须注明「针对她{X}性格」。未挂性格即未过检。

### ★ 心态回指（差评/好评必须回指心态波段）

差评/好评是**表达层切片**，但同一句表达在不同**心态**下风险等级完全不同——必须回指第六节「心态波段分析法」的 8 类标签：

- **每条差评/好评候选，附带「当时她的心态标签 = X」**：X 取自心态波段法的逐句时间轴（统一入口 `band` 已为每条消息带标签，差评/好评条目直接复用，不重算）。
- **价值——区分两种高危误判**：
  - 差评落在其**防御 / 脆弱**态（而非中性态）→ 是被否定感放大（高焦虑雷区触发），整改要"先接住再点射"；落在**热忱**态下的玩笑式吐槽 → 属 A6 合法形态，不拦。
  - 好评落在她**回避 / 防御**态 → 空泛赞美会被读成客套（PR1）或被围观（PR4），必须挂具体事实、走私聊；落在**热忱**态 → 正常接收，可轻量点射。
- **与性格滤镜的关系**：心态 × 性格二维叠加——"她在防御态 + 高焦虑"的差评，风险远高于"防御态 + 低焦虑"。回指时两维都要写。
- **启发式声明**：心态标签是词典近似，回指处一律重申"以原文为准"，不得把回指当事实断言。

### 与既有规则的关系
差评/好评**不新设红线**——差评侧受 R1（不得因差评后变冷／撤回否认）、R3（不得公开或人格压制）、不处表态位、VOL 时序门控、字数红线约束；好评侧受三条实战铁律（只点射、留白、无时差）与 R2（不得把夸当 abundance 表演）约束。本节的增量是把它们**在这两类表达上合拢**，并给出"想说也能说"的合法形态（A1／A3／A6 ／ G1／G3）。

## 九、异动分析法（原「需求异动（选品）法」）：多维画像 → 异动检测 → 归因 → 应对

> **它回答什么**：她是个什么样的人（价值观／三观／性格／兴趣／谈话风格），**以及这些维度最近在往哪变、为什么变、我该怎么调整**。
> **与 VOL 的关系（不覆盖）**：VOL＝**突发事件**下的短窗波动（冲击—恢复，天级）；本方法＝**长期维度漂移**（周—月级）。两者互补：VOL 抓"出事那几天"，本方法抓"这几个月的走向"。
> **前置（硬要求）**：质性维度（价值观／兴趣／称呼／亲密表达）的"异动"证据，**必须来自第六节逐句扫描的时间轴**——先定位"这句话是哪天说的、在哪个波段里"，再做前后对照。**不许凭印象举引文**。统一入口已按波段归组输出近期引文（`recent_quotes_by_band`），直接从中挑，不要凭记忆举。

### 步骤 1 · 选品（建立维度清单）
沿用 `persona-engine.md` 的 12 维作为**骨架**，本方法另补 6 个漂移敏感维度：

| 类别 | 维度 | 证据形式 |
|---|---|---|
| 价值观／三观 | 金钱观、家庭观、婚姻观、忠诚与边界、工作伦理 | **原文引文**为主 |
| 性格 | 主动性、要强／示弱、幽默感、攻击性、焦虑水平 | 引文 + 指标 |
| 兴趣 | 吃什么、玩什么、关注什么内容、消费取向 | 引文 |
| 谈话风格 | 句长、提问率、表情／图片、玩笑密度、正负比 | **指标**为主 |
| **亲密表达**（补） | 称呼、暧昧度、肢体话题、专属梗 | 引文 + 频率 |
| **边界与拒绝方式**（补） | 怎么说不、是否给理由、理由可否验证 | 引文 |
| **承诺与未来指向**（补） | 提"我们"、提未来、是否反提 | 引文 |
| **时间投入**（补） | 活跃时段、日均条数、回复时延 | 指标 |

> **选品原则**：每个维度至少要有一条**原文引文**或一个**可算指标**，二者缺一即降级为"假设"。

### 步骤 2 · 建立基线
- 窗口：默认取**前 2/3 时段**为基线、后 1/3 为近期（`--split` 可调）；同时输出**按月序列**看趋势，避免被单一窗口切分误导。
- 基线必须写清**时间范围与样本量**；样本 < 200 条或覆盖 < 3 周时标注低置信度。

### 步骤 3 · 异动检测（**两类都要做，缺一不可**）

#### 3A 量化维度（谈话风格 / 时间投入）
- 对每个可量化维度算 **drift = 近期 ÷ 基线**。
- **显著异动阈值**：≥ **1.3**（升）或 ≤ **0.7**（降）；0.7–1.3 之间记"微动"，不作为结论主证。
- **方向要分开读**：量升≠更投入，量降≠冷淡——须与**时延、提问率**联合判（同 VOL 的判读金标准）。

#### 3B 质性维度（价值观 / 三观 / 性格 / 兴趣 / 亲密表达 / 边界）
量化指标**回答不了**「她的价值观、性格、兴趣往哪变了」。质性维度必须单独检测：

1. **建主题词表**：每个维度一组关键词（脚本内置 22 个维度，可按案例扩充 `DIMS`）。
2. **算提及密度**：命中句数 ÷ 该窗总句数 × 1000（**每千条**），消除两窗长度不等的偏差。
3. **判定状态**：
   | 状态 | 条件 | 含义 |
   |---|---|---|
   | **新出现** | 基线 0 → 近期 >0 | 一类话题**首次登场**，通常对应一个真实事件 |
   | **消失** | 基线 >0 → 近期 0 | 一类话题**彻底不提**——查是不是踩了禁区 / 话题被你接走了 |
   | **显著上升** | drift ≥ **1.5** | 她最近**更常谈**这个 |
   | **显著下降** | drift ≤ **0.67** | 她最近**回避**这个 |
   | **平稳** | 0.67–1.5 | 不作为结论主证 |
4. **低样本门禁**：基线或近期命中 **< 3 条** → 状态后缀标「（低样本）」，**不得当结论主证**（基数 1 条涨到 8 条就是 8×，纯噪声）。
5. **排除词表**：防同形不同义误匹配——「玩手机」「玩玩」不是「兴趣·玩什么」；「我们公司」不是「未来指向」。命中排除词则不计。
6. **必附带说话人的引文**：每个异动至少 1 条原文引文。

> **质性异动最容易犯的错**：把**谈论第三方**当成**她自己的价值观**。
> 实测反例：她的「忠诚与边界」维度"新出现"，引文是「这是出轨的那个？」「你猜她为什么要出轨」——
> 那是 9/3 她在讲**前夫和别人**，不是在讲你们的边界。**必须回到原文确认「这句话是关于谁的」**。

### 步骤 4 · 归因（四象限，**按顺序排查，不得跳步**）
| 象限 | 含义 | 例 |
|---|---|---|
| **A 外部事件** | 工作、家庭、健康、行程、医美等 | 她近期加班／回家 |
| **B 关系事件** | 约定、见面、冲突、你的某句话 | 9/15 约定后闪烁词变化 |
| **C 内在周期** | 生理／情绪周期、考察期推进、依恋激活 | 考察期后半段更谨慎 |
| **D 自身行为触发** | **你的行为造成的**（加压、补位、差评、冷淡） | 你发起变多 → 她发起变少 |

- **判定规则 1（时间对齐优先）**：异动起点是否落在某事件的 ±2 天内？对齐才归因，不对齐不得硬套。
- **判定规则 2（禁自利归因）**：**必须显式检查 D**，并写出"这一项有没有可能是我造成的"。把 D 归成 A/C 是本方法最常犯、也最致命的错误——因为它会把"我该改"变成"她变了"。
- **判定规则 3（补位效应）**：一方某项行为上升，常导致另一方同项下降（发起、提问、安抚皆如此）。看到对方"退位"，先查自己是否"补位"。

### 步骤 5 · 应对（对因下药 + 验证指标）
- 每个归因给**一个动作**，不给一串。
- **必须附验证指标**：写清"怎么知道应对生效"（例：她的发起占比回升至 ≥0.4；闪烁词回落；msgs_per_day 不降）。
- 应对须过 R1/R2/R3 与"不处表态位"；涉负向表达时过**第八节五道闸**；涉正向表达时过 G1–G6。

### 置信度与可证伪
- 标置信度：**窗口切分敏感性**（换切分点结论是否翻转）、**样本量**、**单事件驱动**（一个事件带出全部异动 → 低置信）。
- 给**推翻条件**：例"若她的发起占比在两周内回到 ≥0.4，则'她退位'的判断不成立"。

### ★ 引文硬要求：每一句都要能回答「这是谁说的」
- 脚本层：所有引文对象**必须带 `who` 字段**（`band.json` 的触发句 / `pb.json` 的差评好评条目 /
  `drift_qual.json` 的代表引文 / `analysis_all.json` 的 `recent_quotes_by_band`）。
- 报告层：引文一律写成 **`她·9/15：「…」`** 或 **`你·9/21：「…」`** 的形式。
  **禁止出现没有主语的裸引文**（❌「闭关半个月」✅「你·9/18：「你差不多得在家里『闭关』半个月」」）。
- 归因层：凡用引文支撑的归因，必须说明**这句话是谁说的、说给谁、说的是谁**——
  她讲前夫 ≠ 她对你的态度；你说的话不能当她的证据。

### ★ 结合人物性格滤镜（异动必须回性格基线读）

- **「变」要先判是性格触发还是真变**：某项维度漂移，先看它是否落在她的**性格缺点 / 雷区**触发条件上——若是，这"变"可能是你踩了雷区导致的**应激反应**，而非她本人长期变了（例：她突然回避，可能是你一句差评触发反刍，不是她对你冷淡了）。优先查 D（自身行为触发）。
- **踩中雷区的异动优先处理**：若漂移维度恰好对应她的雷区（如高焦虑者的"确定性需求"维度上升），它的优先级高于普通漂移——因为它会连锁放大多项指标。
- **性格优点维度的正向漂移可倚仗**：若漂移落在她的性格优点入口（如"主动示弱"上升），这是推进关系的窗口，方案要顺着它走。
- **跨周期看性格是否漂移**：单次异动可能是事件驱动；只有**周期跟踪**（步骤 6）显示同一维度连续多周期同向漂移，才能断言"她这个人变了"。一次数据不得下"性格变了"的结论。

### ★ 心态回指（异动必须回指心态波段）

维度漂移是**宏观**的，但"她在这个维度活跃期的心态是什么"决定了它是推进窗口还是风险窗口——必须回指第六节「心态波段分析法」：

- **每个质性维度漂移，附带「该维度活跃期她的心态整体偏 X」**：取该维度引文所对应的波段标签，做**整体概括**（偏热忱 / 偏防御 / 偏脆弱 / 平稳），**不做逐句贴标签**（宏观维度逐句贴会碎片化，失去漂移意义）。
- **价值——区分"真推进"与"压力性异动"**：
  - 「承诺」维度新出现 + 同期心态**偏热忱** → 是她主动靠近的推进窗口，方案顺着走。
  - 「承诺」维度上升 + 同期心态**偏防御** → 可能是压力性承诺（被催出来的），要警惕，方案改为"不追定义、用行动兑现"。
  - 「示弱与依靠」新出现 + 同期心态**偏脆弱** → 是开放信号（接住会升温），不是负向。
- **与性格滤镜、周期跟踪的关系**：心态回指和性格滤镜（步骤前文）是同一维度的两面——性格滤镜回答"这变是不是踩雷区"，心态回指回答"变的时候她是什么状态"；二者都需**周期确认**（单次心态概括可能是事件驱动，连续周期同向才记趋势）。
- **启发式声明**：心态标签是词典近似，回指处一律重申"以原文为准"。

### 步骤 6 · 周期跟踪（跨上传增量对比 · 用户要求的「周期性分析」）

> **目的**：单次分析容易被单一窗口误导（一个事件带出全部异动）。用户要求「周期性分析」——每次上传新记录，都做一次与上次的**增量 diff**，看四层方法分析法的核心指标是否跨周期漂移。

- **做法**：① 保留上次的 `analysis_all.json`（或四个 json）作为**基线快照**；② 新上传解析后跑同一套 `analyze_all.py` 得到**本期快照**；③ 对比四张核心卡（每项写「上次 → 本期 → 方向 → 是否落在性格雷区」）：
  | 层 | 对比指标 |
  |---|---|
  | 波段 | 基线趋势均值 vs 本期；Top 降温点数量与触发句类型是否变化 |
  | VOL | 危险型（抽离）事件数 vs 上期；平均恢复速度 |
  | 差评/好评 | 差评候选数 / 真实差评数 / `pos_neg_ratio` |
  | 异动 | 量化 drift 矩阵；质性「新出现 / 消失」维度是否**持续**（而非一次事件） |
- **观察周期建议**：高频关系每 **1–2 周**上传一次做增量；低频按**事件驱动**（每次大事件后上传）。**单次分析不得下"性格变了"结论**，必须周期确认。
- **阈值门控**：只有**连续 ≥2 周期同向漂移**才记为「趋势性变化」；单周期波动标「观察中」。
- **输出**：在报告里以 **十二、周期性分析** 小节（见 output-templates FULL 结构）呈现跨周期对比卡。

### 工具
- `scripts/drift_analysis.py <chat.txt> --self <本人> --other <对方> [--split 0.67]` → `drift.json`（**量化**维度：基线 / 近期 / drift / 按月序列）。
- `scripts/drift_qual.py <chat.txt> --self <本人> --other <对方> [--split 0.67] [--side other]` → `drift_qual.json`（**质性**维度 22 项：状态 / 每千条密度 / drift / 低样本标记 / **带 who 的引文**）。`--side` 可选 `other`（默认，只看她）/ `self` / `both`。
- 统一入口 `scripts/analyze_all.py` 会同时跑这两类，输出 `drift`（量化）+ `drift_qual`（质性）。

## 十、验证门（Grill Gate · 吸收 grill-me 机制，不套其外壳）

> **来源与改造**：机制取自 `mattpocock/skills` 的 grill-me（方案拷问：一问一答、每题给推荐答案、**事实自己查只问需你拍板的**、确认前不动手）。
> **只吸机制，不套外壳**：grill-me 拷问的是**待实施的方案**，而本引擎 90% 的活是**分析已发生的历史**——历史不能被"拷问"。
> 因此本门**串联在四大方法之上**（不是第五个方法），且做了四处改造（见末尾「与 grill-me 原版的差异」）。
>
> **触发时机**：Step 3.6 归因结论产出之后、Step 4 行动方案与话术落地之前。**FULL 模式必过**；QUICK/SNAPSHOT 跳过 G1、只做 G2 的事实声明。

### G1 框架拷问（**先于计划**，grill-me 原版没有，本引擎必须加）
> 为什么必须先加这道：grill-me 只拷问「计划内部的决策分支」，**不拷问框架本身对不对**。
> 实测教训：用户带着「博弈 / 高位低位」框架来问，顺着答会产出漂亮但错误的结论——若当时有 grill-me，它会把那个**错误框架打磨得更严密**。

出结论前，先对自己过三问（**任一不过即打回重做**）：
1. **更简单解释**：有没有一个更朴素的解释，能同时覆盖这批指标？（例："她发起变少"→ 是她退了，还是你开口变多了？后者更简单、且可算）
2. **框架溯源**：这个结论是不是顺着用户带进来的框架走出来的？如果是，**先核验框架**（用指标），不核验就不得出结论。
3. **反向证据**：哪些证据能推翻它？**先写出推翻条件，再写结论**（不允许结论在前、推翻条件补在后面）。

### G2 事实 vs 决策分工（grill-me 的核心，本门最值钱的部分）

**⚠️ 用户口径（2026-09-27 定，最高优先）**：**能从聊天上下文读出来的，一律自己读、自己判，不许甩回给用户确认。**「待你确认」不是流程图上的必经环节，而是**穷尽上下文后的极小残余**。

把每个归因拆成三张清单，**不许混在一句结论里**：

| 清单 | 谁回答 | 规矩 |
|---|---|---|
| **已查事实** | **脚本 + 上下文**（不问用户） | 每条标来源：脚本值标 `脚本:字段`；**上下文推出的事实标 `上下文:日期·谁：「原文」`**。例：发起占比 0.588 ← `analyze_all.py → drift.initiative_share`；「三处行程是你先提的」← `上下文:9/25 17:34 你：「不行咱还可以去跑马场…」→ 17:34:34 她：「累了，我还是想回小泉州」` |
| **已推定（带因果链）** | **引擎自己判**（不问用户） | 上下文推出的**判断类**结论（谁先发起、谁在回应谁、某动作是主动还是被动）。必须附**因果链三要素**，且标置信度。这是本版新增的主产物，**不再降级成问题问用户** |
| **待用户确认** | **只有用户知道** | 压缩到极小。**判断标准见下方「三、什么才真的问」**；每条仍须附推荐答案 + 替代方案 |

- **硬规矩 1**：**凡是能从聊天记录里读出来的，不许问用户**——问了就是把本该引擎干的活甩回去（用户 2026-09-27 明确要求，见下方「上下文自判原则」）。
- **硬规矩 2**：脚本与上下文都查不到的，**不许假装已确认**。**启发式标注（波段标签、差评候选、质性维度命中）一律不是事实**，只是候选；不得因为走完流程就升级为事实。
- **硬规矩 3**：关系领域最关键的（**她到底怎么想的 / 动机 / 有没有生气**）**永久标「不可查」**。任何把它写成事实的归因，一律打回。
- **硬规矩 4**：**「上下文推定的」必须与「脚本算出的」区分开**，且**必须给因果链**（见下节）。没有因果链的时间相邻，**只能叫「关联」，不能叫「原因」**。

---

#### 一、上下文自判原则（本版核心 · 用户 2026-09-27 要求）

> 用户原话：**「类似这种问题自己读取上下文，自己判断，不要再写带我确认。」**

- **顺序**：得出一个归因 → **先在聊天记录里穷尽搜索证据** → 能定的**直接定**（写进「已查事实」或「已推定」）→ 只有**搜完仍无法从文字判定**的，才进「待用户确认」。
- **典型可自判（原来错问、现已全部改自判）**：
  | 原来问用户 | 现在怎么自判 |
  |---|---|
  | 这个安排是她先问的还是你主动给的？ | **读时序**：谁的那条在前、谁在接话。前一条是她的诉求、后一条是你在给信息 → **你主动给的**。原文见 `上下文:9/25` |
  | 对方说的忙，是她自己说过还是你推测的？ | **全文检索她的口吻**：出现「我…忙/累/没空/开会」＝她自己说过；只有你在转述＝你推测的 |
  | 这个邀请是谁起头的？ | 向上回溯到**该话题第一句**，谁发出的即谁起头 |
  | 某句「同意」是真心还是敷衍？ | 看**该句的下文是否续接**：续接＝真接住；仅「好/嗯」后无跟进＝低投入（标为已推定，非事实） |
- **禁**：把上面这类问题原样写进报告问用户。**写了即为未过检**。

#### 二、因果链判定（增强真实性 · 用户 2026-09-27 要求）

判定「X 导致 Y」时，**必须给三段链**，缺一不可：

| 要素 | 要求 | 反例（不许这样判） |
|---|---|---|
| **① 时间在先** | X 的时间戳必须**早于** Y，并写明两条原文的时间差 | 「她说完之后就降了」——没给 X 的时间戳 |
| **② 状态在先** | X 发生前，对方的状态已知（引她发话前的波段标签 / trend 值） | 不知道她发话前什么心态就断言被这句话打到 |
| **③ 排他性** | 排除同期其他候选原因（外部事件 / 她的周期 / 你自己另发的消息），并说明为何排除 | 当天还有其他刺激却只归给这一句 |

- **输出格式**（写进归因卡片）：
  ```
  因果链：① X（谁·时间戳·原文）→ ② 她当时状态（波段标签 + trend，来源 band）→
          ③ 排除项（同期她还在处理___；你另有___句，已排除）→ 结论
  ```
- **红线**：**只满足 ① 的叫「时间相邻」，不叫因果**。任何因果结论缺 ② 或 ③，一律降级为「关联」并标注。
- **本次实例**（可直接对照）：9/25 17:34:01 **你**提三处行程 → 17:34:34 **她**回「累了，我还是想回小泉州」→ 17:34 波段 −1.40。因果链正确写法：**是你先给安排、她以「累」拒绝**，而非「她先要安排、你塞行程把她压到 −1.40」。**方向判反就是致命错**（见下方「反面案例」）。

#### 三、什么才真的问（「待确认」的准入清单）

只有同时满足以下**全部**条件的，才允许进「待用户确认」：
1. **文字里没有**（穷尽检索仍无）；
2. **不是她的内心想法 / 动机**（那些永久「不可查」，不问、直接标不可查）；
3. **只有用户本人在场才知道的线下事实**（例：当面有没有牵手、见面时她的表情语气、你是否已线下做过某事）；
4. **会实质改变结论或行动**（无关紧要的不问）。

> 结论：**「待确认」通常 0–1 条**。若某份报告又冒出 3 条以上「待确认」，先怀疑自己没查上下文。
- 交互仍受 grill-me 约束：**一次一问**，每题附**推荐答案（自动选定）+ 替代方案**。

#### ★ 反面案例（2026-09-27 实测，必须记住）

本次报告原本写了 3 条「待你确认」，**逐条回原文后，3 条全部可以从上下文自判，且其中 1 条把因果链判反了**：

| 原「待确认」问题 | 回原文后的真相 | 错在哪 |
|---|---|---|
| 「9/25 跑马场/学生街/三坊七巷，是你主动给的，还是她先问的？」 | **你先提的**。`你·9/25 17:34:01：「不行咱还可以去跑马场、学生街、三坊七巷那边看一下。顺便垫垫肚子」` → 18 秒后 `她·17:34:34：「[呲牙]累了，我还是想回小泉州」`。她全程未索要行程 | **原报告把它写成「她先说累了 → 你连加行程」**，把**你先给安排**误读成**她先提需求**，**因果方向判反** |
| 「你发起 0.588，是你开口变多，还是她回得慢你补一句？」 | **她时延不快但也没慢**（多数 ≤1×），你发起占比高＋她条数 1.15× 上升 → **你补位**。可从 VOL 时延数据自判 | 脚本已能算，却在问用户 |
| 「她 9 月忙是她说过还是你猜的？」 | **她自己说过多次**：`她·9/11：「开了两天的会，忙死了都」`、`她·9/24：「今天有点忙」`、`她·9/16：「今天晚上没空，跟同事约逛街」`。原文旁证充分 | 全文可检索，却在问用户 |

> **教训**：这 3 条**一条都不该问**，全部属于「读了上下文就能定」。另外 2 条引用的旁证也错了——原报告拿 `她·9/18「告诉你别太卷了」` 当「她说过自己忙」的证据，但那句是 **9/2 说的、而且是说你在卷**（`她·9/2 22:19:37：「告诉你别太卷了，下班还聊工作」`）。**引文必须核对时间戳与说话人**，错引比不引更危险。

**★ 待你确认的「推荐答案」必须自动选定（原规则保留）**
> 用户原话要求：归因卡片的选择方向，**由系统根据聊天上下文 + 对方心态分析自动选定一个方向**，不是把选项平铺让用户自己挑。
- **怎么做**：每一条「待用户确认」都先由引擎结合（① 本段聊天上下文的时序与主语归属；② 她的波段 / VOL / 异动心态指标）**自动推一个最可能方向**作为「推荐答案」，并写出**自动选定依据**（哪段记录、哪个心态指标支持这个方向）。
- **必须同时给翻转条件**：写明「若 X 成立，则改选替代方向」——这才是自动选定，不是武断下结论。
- **用户拍板权不变**：自动选定的方向只是推荐，最终仍由用户确认；G4 确认门照常锁话术与行动。
- **禁止**：把"推荐答案"写成"看你怎么想"式空话，或回避自动选定（那等于把本该引擎做的判断甩回给用户）。
- **⚠️ 优先自判**：若该题**其实能从上下文自判**（见「上下文自判原则」），则**不许**立成「待确认」——直接判完写进「已推定」，连推荐答案都不必给。

**归因卡片格式（每条归因必带 · 2026-09-27 改版）**：
```
结论：……
置信度：高 / 中 / 低
① 已查事实（脚本 + 上下文，带来源/时间戳/who）：①…（脚本:字段）②…
② 因果链（判因果时必写）：X（谁·时间·原文）→ 她当时状态（波段/trend）→ 排除项 → 结论
③ 还依赖哪些待用户确认的未知：①…（推荐答案：…｜替代：…）   ← 通常为「无」
不可查部分（明确承认）：她当时是否……（内心动机，永久不可查）
推翻条件：若……则本结论不成立
```

### G3 行动方案拷问（可执行性，只在 Step 4 用）
每条动作出方案前问一句，并给推荐答案：
- **耐受拷问**：「如果她连续 N 天没反应，你扛得住吗？」扛不住 → 这条作废，换一条你能执行的。
- **口径**：一次一问，每题附**推荐答案 + 至少一个替代方案**（照搬 grill-me 的"每题给推荐答案"）。
- 通不过耐受拷问的动作，**不许写进行动方案**——写了就是自我安慰。

### G4 确认门（HARD GATE · **只锁话术与行动**）
- 在用户明确确认「共享理解」之前，**不产出最终话术、不执行动作**。
- **边界（重要）**：**分析结论不受此门约束**——历史已经发生，分析可以直接给。门只锁「接下来要说什么、做什么」。
- 确认形式：用户明确说「确认 / 就这么办 / 按这个来」等；沉默、换话题、继续追问都不算确认。

### 与 grill-me 原版的四处差异（**不得改回去**）
1. **加了 G1 框架拷问前置**（原版没有）。理由：顺用户框架走是本引擎踩过的最大坑。
2. **"事实"定义收窄**：脚本算出的叫「已查指标」；**她怎么想永久标「不可查」**。原版假设"事实都能自己查"，照搬会诱导把启发式标注当事实——正是本引擎反复踩的坑（波段是近似、VOL 自动锚点会误报"抽离"）。
3. **确认门只锁话术与行动，不锁分析结论**。原版是"动手前"结构，而分析的对象是已发生的历史，不适用。
4. **不引入 `grill-with-docs` 变体**：它要求每个挑战都引真实文档 URL，关系领域没有"官方文档"，强行引等于编造。

### 代价（写清，避免误用）
- 对话轮次会显著拉长（复杂归因可能十几轮）。用户习惯直球要结论，连续被反问易不耐烦。
- 因此：**G1 三问由自己过，不逐条念给用户**；**G3 的耐受拷问才真的开口问**；**G2 的「待确认」已被压缩到 0–1 条**（上下文能读的一律自判，见「上下文自判原则」）——**问得越少越好，能自判就绝不问**。
- **2026-09-27 用户明确表态**：不要再把「上下文可读」的问题写进「待你确认」。所以 G2 现在的重心是**写清已查事实 + 因果链**，而不是向用户提问。
- 与「输出前自检」的关系：**自检是内向自查，验证门是外向质询**，方向相反、互补，不重复。

## 十二、输出前自检

生成方案后逐条过：

1. 性格/人格/类型判断有没有标置信度 + 给证据 + 给推翻条件？→ 没标就补上（判断本身允许，不能无据断言）
2. 每条结论有没有证据？→ 没有就降级为假设或删除
3. 「不做」是不是从风险清单反推的？→ 不是就补上
4. 话术有没有引用真实语境？→ 没有就重写
5. 有没有给出验证方法？→ 没有就补「观察指标」
6. 有没有高危信号（自伤/控制/骚扰/诈骗）？→ 有就额外附一句关注提示
7. **每条话术字数有没有超过「对方上一条 × 1」？** → 超了就砍到上限内（短消息同样适用）
8. **过三条实战铁律** → ①有没有替对方解释细节（只点射不扫射）？②这条读完对方还有可接的吗（50% 留白）？③有没有主动打时间戳（无时差原则）？任一不过就重写。
9. **测试报告/截图类证据先确认归属** → 这份 MBTI/依恋测试是谁做的？用户本人还是对方？没确认前不得把测试结果挂到任何一方头上（实测翻车：把用户的 Sakinorva 报告误读成对方的，导致 Fi-Te 摆动分析张冠李戴）。归属确认前，只采信聊天记录等有明确主语的行为数据。
10. **过「动机护栏」四条红线（R1/R2/R3/R4）** → 话术是否含 push-pull 冷热交替（R1）/ abundance 广撒网暗示（R2）/ 高位打压框架压制（R3）/ 极左极右速决或把"马上断联"当解法（R4）？任一命中即拦截改写，并在输出中注明「已按红线拦截」。R4 专项：方案是否给清**最终目的 + 分阶段步骤**、是否**按对方性格定制**、决策里**有没有把"马上断联 / 冷处理"当解法**——有即改回"目的 → 渐进步骤"。详见「动机护栏 R4」一节。
11. **做 VOL 判读时是否以时延为准、量能为辅**？→ 把「对方回复变少」直接读成「变冷」是典型误判；须看 `latency`（回复时延）是否同步上升。量降 + 时延不升＝**压力缩量**（处置：减压）；量降 + 时延升 + 提问降＝**抽离**（处置：给空间 + 可证伪检验）。事件窗数据不足须标注，不得外推。详见「VOL（心态波动率）分析」。
12. **差评类表达是否过了五道闸**？→ 凡指向对方的负向输出（吐槽 / 负面评价 / 直白批评 / 强要要求），发出前必过：① 说的是"我"的感受还是"你"的评价（TR1/TR2）；② 只针对这一次行为还是上升人格（TR6）；③ 是可拒的请求还是命令（TR3）；④ 是否落在她的压力窗 / 见面后回落窗 / 承诺后焦虑窗（TR5，见 **VOL 第七节**）；⑤ 是否走私聊（TR10）。任一不过 → 改写成 A1（感受陈述）/ A3（可拒请求）/ A6（三句式反馈）。发出后**不撤回、不解释、不追问**（TR8/TR9）。详见「差评/好评分析法」一节。
13. **拦截时是否走了「疏导四步」**（接住情绪 → 提取并命名需求 → 肯定需求 → 才判手段 + 给合法路径）？只判手段不疏导＝指责。是否写出了「这个动作真能满足它想满足的那个需求吗」这一句？是否给了**满足同一需求**的合法路径？连续拦截 ≥ 2 次时是否已申明「拦的是动作不是你/你的情绪」并列出通过的部分？详见「需求疏导优先于手段判定」。
14. **做维度异动分析时是否显式排查了 D（自身行为触发）**？→ 每给出一项"对方变了"的结论，必须同时回答"这一项有没有可能是我造成的"，并查**补位效应**（我某项上升是否挤掉了她的同项）。禁止把 D 归成 A（外部事件）或 C（内在周期）——这是自利归因，会把"我该改"变成"她变了"。异动是否给了**验证指标**与**推翻条件**、是否标了置信度与窗口敏感性？详见「**异动分析法**」。
14b. **异动分析是否两类都做了、引文是否都标了说话人**？→ ① **量化维度**（drift_analysis：条数/句长/提问率/时延/发起占比）；② **质性维度**（drift_qual：价值观/三观/性格/兴趣/谈话风格/亲密表达/边界）。只做量化＝没回答「她这个人往哪变了」。质性结论是否标了**低样本**（命中 <3 条不得当主证）？是否回原文确认了「这句话是关于谁的」——**她讲前夫 ≠ 她对你的态度**。③ **报告里每一句引文是否写成「她·日期：原文」或「你·日期：原文」**？出现没有主语的裸引文即未过检。详见「异动分析法」步骤 3 与「引文硬要求」。
15. **是否先做了逐句扫描（第六节），再谈 VOL / 差评好评 / 异动**？→ 三个方法**共用同一份逐句标注时间轴**：事件锚点取自波段升降点，正负向表达取自标签筛选，质性异动的引文须定位到具体日期与所在波段。**凭印象挑句子 = 未过检**，必须重跑 `scripts/band_analysis.py`。是否声明了词典标注的**启发式性质**（关键句需人工复核）？波段与 VOL、异动结论冲突时，是否以**人工复核的原文**为准？详见「心态波段分析法」。
16. **是否用了统一入口、且自动锚点已确认**？→ 是否跑 `analyze_all.py`（一次读取、四层方法分析法共享同一份逐句时间轴）？单跑各脚本时口径是否与统一入口一致（词表、会话间隔 7200s、question_ratio 按句计）？**VOL 与异动是否也做了逐句复核**（VOL 回到窗内原文；异动引文定位到日期＋波段）？凡 `needs_confirm: true` 的事件是否被当成结论直接写进报告——**自动锚点判出的「抽离」多半是低量日噪声**。详见 Step 3.6、Step 3.7 验证门 与「VOL」一节。
17. **好评是否过 G1–G6**？→ 夸了有没有**具体锚点**（G1）、是夸行为还是夸角色（G2 / PR3）、是否与请求同条发出（G3 / PR7）、是否落在她的压力窗或术后恢复窗且夸了外貌（G5 / PR5）、差评前后 24 小时有没有加码好评（PR6）。空泛赞美与高密度赞美同样要拦。她夸你时是否**接住并回指具体**、没有自贬反问（G6）。
18. **FULL 模式有没有过验证门 G1–G4**？→ ① **G1**：用户带来的框架（博弈 / 高位低位 / 谁爱谁更多）有没有被先拷问？（有没有更简单的解释？框架从哪来？有没有先写推翻条件？）② **G2**：每条归因有没有分成「**我查得到的事实**」与「**只有你能确认的事**」两张清单？她的想法 / 动机 / 有没有生气，是否已标为「**不可查**」而不是被写成事实？「待你确认」的问题是否一次一问、每题带推荐答案 + 替代方案？③ **G3**：行动方案有没有过耐受拷问（最坏情况你接得住吗）？④ **G4**：确认前有没有动**话术与行动**（分析结论不受锁）。把「她的想法」当事实直接写进结论、或未经确认就发出话术＝未过检。QUICK/SNAPSHOT 可跳过 G1，但 G2 的事实声明不可省。详见「**验证门（Grill Gate）**」。
19. **有没有把「上下文可自判」的问题甩回给用户**（2026-09-27 新增 · 必查）？→ 列出报告里所有「待你确认 / 待确认 / 请你确认」条目，逐条回**全文检索**：① 这条能否从聊天记录读出来（谁先发起、谁在回应、对方有没有亲口说过）？**能读出来的一律删掉，自己判完写进「已查事实 / 已推定」**；② 剩下的条目是否满足「待确认准入清单」四条（文字里没有 + 非她内心 + 线下在场事实 + 影响结论）？③ **「待确认」条目是否 ≤1 条**？超过就说明上下文没查够。**凡把「谁先发起 / 是不是她说的」这类可读事实写进问题 ＝ 未过检，必须重写**。详见「上下文自判原则」。
20. **因果结论有没有给全三段链**（2026-09-27 新增 · 必查）？→ 凡出现「因为…所以…」「…导致她…」「她说完…之后…」，逐条核：① **时间在先**（X 的时间戳早于 Y，且写出时间差）？② **状态在先**（引她发话前的波段标签 / trend 值）？③ **排他性**（排除同期外部事件、她的周期、你自己另发的消息）？**缺 ② 或 ③ 的一律降级为「关联」并标注**；只满足 ① 的「时间相邻」不得写成因果。**方向必须回原文核**：谁先谁后、谁在接话——**判反方向是致命错**（实测踩过：把「你先给安排、她以累拒绝」错判成「她先要、你压到她」）。详见「因果链判定」。

21. **话术有没有说人话、加标点、通顺**（2026-10-22 新增 · 必查）？→ 每条出给用户的候选话术，读一遍过四问：① **有没有抽象概念化描述**（对方要"翻译"才懂，如"你对我意义是一种…""我本质上…"）？② **长句有没有断句**（一整段无标点）？③ **逻辑是否跳跃／绕**（自嗨联想、看不懂的起手）？④ **语气是否松弛**（适当口语词「呗／哈／啦」，别像写稿）？任一不过＝重写。若聊天记录里对方曾给过「讲人话／加标点／你这说的什么」类表达指令，**优先改这一条**。命中＝规避 AI 感的第一道防线，与微纪律"指令后闭嘴"同链。详见「表达质感 · 说人话」。
